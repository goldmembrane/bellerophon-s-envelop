# Detailed Implementation Plan

이 문서는 MVP 18단계 이후의 상세 구현 순서를 정리한 계획서다. 기준 문서는 `docs/GAME_DESIGN_SOURCE.txt`이며, 원본 기획서와 충돌하는 경우 원본 기획서와 사용자 확인 사항을 우선한다.

## 문서 상태

- 상태: 원본 기획서 대조 수정본.
- 구현 원칙: 이 문서의 각 단계는 구현 전에 해당 단계 범위를 다시 원본 기획서와 대조한다.
- 온라인/멀티플레이: Steam 로비, 온라인 접속, 최대 5인 동기화 구현은 상세 싱글 플레이 구현 이후 별도 설계 게이트에서 다룬다.
- 금지: 화물 직접 집기, 운반, 직접 납품 상호작용은 구현하지 않는다. 화물은 의뢰, 운송 상태, 정산, 개인 화물 상점 판매의 대상이다.
- 사용자 확인 사항이 필요한 항목은 하단 `사용자 확인 필요 항목`에 모은다.

## 원본 대조 정정 사항

- 상태 이상 목록은 원본 기준으로 `정지`, `화상`, `출혈`, `탈진`, `피로`, `현기증`, `혼란`이다. `감전`, `둔화`, `환각`, `공포`는 원본 상태 이상 명칭이 아니므로 사용하지 않는다.
- 무기 명칭은 원본 기준으로 `전류봉`이다. `전기봉`으로 쓰지 않는다.
- 치료/강화/기타/특별 물품 분류는 원본 상점 분류를 따른다.
- 은폐 블랙홀은 원본에 세부 수치가 있으나 사용자 확인에 따라 후반 위험 확장으로 미룬다. 11단계에서는 원본 수치와 조건만 문서화하고 구현하지 않는다.
- 씨앗체 두 번째 개체 명칭은 사용자 확인으로 `푸가`로 확정한다.
- 미메시스의 “유저 목소리 저장/흉내”는 원본 기능이다. 싱글 플레이에서 시각/신호 mimic으로 축소하려면 별도 사용자 확인이 필요하다.
- 해적 개체 명칭은 원본 기준 `파후르`, `쿠르사`, `이슈판트`, `아타`다.

## 현재 구현 상태

- 상세 구현 1~12단계는 완료된 상태로 본다.
- 상세 구현 11단계는 은폐 블랙홀을 후반 위험 확장으로 보류한 상태에서 소행성 小/大, 화물 자유 연대, 우주 해적, 외계 생명체 외부 위험 구간까지 구현했다.
- 상세 구현 12단계는 침입자 공통 목표, 방/복도 경로, 통제실 손상 영향, 적대 세력 관계 모델을 구현했다.
- MVP 18단계까지의 시작, 협회 계약, 튜토리얼 운송, 자동/수동 운행, 외부 위험, 수동 포탑, 정산, 정비, 후속 운송, Parvum 침입자, 장비 루프, HUD/맵/분위기, 로컬 협동 상태 경계, 반복 플레이테스트 smoke가 존재한다.
- `IPlatformServices`, `IPlatformMultiplayerServices`, `NullPlatformMultiplayerServices` 경계는 있으나 실제 Steam 또는 온라인 네트워크 기능은 붙이지 않는다.
- 열린 Unity 에디터의 generic PlayMode Test Runner callback 불안정성은 알려진 문제다. 기능별 PlayMode smoke는 계속 필수 검증 경로로 사용한다.

## 공통 구현 원칙

- 순수 게임 규칙은 가능한 한 `MonoBehaviour` 밖 Runtime 모델로 분리하고 EditMode 테스트를 붙인다.
- 입력, 카메라, UI, 씬, 물리처럼 Unity 오브젝트와 연결되는 기능은 PlayMode smoke를 추가하거나 기존 smoke를 확장한다.
- 원본 기획서의 수치가 있는 항목은 임시 수치로 대체하지 않는다.
- 원본 내부가 상충하거나 수치가 빠진 항목은 구현 전에 사용자에게 확인한다.
- Steam, 저장, 업적, 클라우드, 온라인 멀티 같은 플랫폼 기능은 인터페이스 뒤에 둔다.
- `Library`, `Temp`, `Logs`, `UserSettings`, `Builds`, `TestResults`는 생성물로 취급한다.

## 공통 검증 사다리

변경 범위에 따라 낮은 단계부터 실행한다.

1. `.\scripts\Run-HarnessValidation.ps1`
2. `.\scripts\Run-EditModeTests.ps1`
3. 해당 단계별 smoke 스크립트
4. `.\scripts\Run-PlayModeTests.ps1` 또는 해당 PlayMode smoke
5. `.\scripts\Build-WindowsDev.ps1`

`Run-PlayModeTests.ps1`가 열린 에디터 Test Runner callback 문제로 실패하면, 해당 단계의 기능별 smoke 결과를 필수 증거로 남기고 Test Runner 안정성 문서에 계속 추적한다.

## 1단계: 상세 구현 기준선 정리

목표: MVP 18단계 이후의 상세 구현을 위한 데이터, 테스트, 문서 기준선을 고정한다.

구현 범위:

- 현재 MVP 상태를 상세 구현 기준선으로 정리한다.
- `docs/MVP_PLAYTEST_CHECKLIST.md`를 상세 구현 회귀 체크리스트로 확장한다.
- 원본 기획서의 수치가 코드에 이미 존재하는지 확인하고 중복 상수와 임시 수치를 문서화한다.
- 행성, 항로, 의뢰, 화물, 방, 장비, 적대 세력, 위험 구간의 Runtime 데이터 뼈대를 정리한다.
- Unity `ScriptableObject` 카탈로그보다 순수 C# 데이터/규칙 모델을 우선한다.
- PlayMode Test Runner 안정성 이슈를 재검증하고, 실패 시 추적 문서에 남긴다.

검증:

- Harness validation
- EditMode tests
- Phase18 MVP smoke
- `.\scripts\Run-PlayModeTests.ps1`
- Windows 개발 빌드

완료 기준:

- Phase18 반복 루프가 기존과 동일하게 통과한다.
- 이후 단계에서 사용할 데이터 타입과 테스트 분류가 문서화된다.
- PlayMode Test Runner 상태가 `docs/PLAYMODE_TEST_RUNNER_STABILITY.md`에 추적된다.

## 2단계: 행성, 항로, 의뢰 데이터 모델

목표: 행성 특성, 항로 거리, 의뢰 유형, 난이도, 보상 산식을 MVP 임시 목록에서 분리한다.

구현 범위:

- 행성 특성은 원본 명칭을 따른다: `물이 풍부함`, `기본 광물 풍부함`, `유기체가 많음`, `희귀 광물 풍부함`, `나무 풍부함`, `화산 활동 활발`.
- 행성은 원본처럼 하나 이상의 특성을 가질 수 있게 모델링한다.
- 항로는 출발 행성, 목적지 행성, 운행 시간, 위험 구간 후보, 거리 산식 입력을 가진다.
- 의뢰 유형은 `협회 의뢰`, `개인 의뢰`, `특수 의뢰`로 분리한다.
- 의뢰 난이도는 원본의 7단계인 `입문`, `매우 쉬움`, `쉬움`, `보통`, `어려움`, `매우 어려움`, `달인`을 사용한다.
- 보상 산식 입력은 운송 화물 가치 60%, 운송 거리 30%, 평판 10%를 추적할 수 있게 분리한다.
- 협회 의뢰 보상은 기본급, 거리 산정 비용, 수리비 지원금, 화물 안전 운송 근속 보너스를 분리한다.
- 개인 의뢰 보상은 화물 등급, 거리 산정 비용, 개인 유명세 프리미엄을 분리한다.
- 의뢰 수락 조건에 창고 운송 점수와 운송창고 상태를 연결한다.

검증:

- 행성 특성 조합 tests
- 의뢰 생성과 보상 산식 EditMode tests
- 첫 튜토리얼 의뢰 회귀 tests

완료 기준:

- 협회 소속이면 협회 의뢰가 5개 이상, 비소속이면 2개 이상 노출되는 규칙이 검증된다.
- 의뢰 보상이 원본 비율과 정산 기준을 추적 가능하게 계산된다.

## 3단계: 의뢰 게시판, 유명세, 협회 경제

목표: 다음 운송 선택 시 협회 의뢰, 개인 의뢰, 특수 의뢰 후보를 구분해서 판단할 수 있게 한다.

구현 범위:

- 정비 화면의 후속 의뢰 목록을 의뢰 게시판 구조로 확장한다.
- 일반 유명세와 협회 유명세를 분리한다.
- 성공, 실패, 사망자, 화물 손실, 난이도에 따른 유명세 갱신 규칙을 추가한다.
- 유명세가 -500 미만이면 개인 의뢰가 사라지고 협회 의뢰 수락 시 협회 가입이 강제되는 규칙을 준비한다.
- 유명세가 기준 아래일 때 게임당 1회 제공되는 회생 의뢰 흐름을 추가한다.
- 협회 유지비와 협회 탈퇴 위약금 데이터는 원본 기획서와 기존 구현 상태를 대조해 정산 입력에 연결한다.
- 협회 탈퇴 UX 자체는 별도 확인 후 구현한다.

검증:

- 유명세 변경 EditMode tests
- 협회/개인 의뢰 노출 조건 tests
- 정산 후 의뢰 게시판 smoke

완료 기준:

- 정산 이후 다음 의뢰 후보가 유명세, 협회 상태, 운송창고 점수에 따라 달라진다.
- 협회 경제의 이득과 비용이 정산 결과와 충돌하지 않는다.

## 4단계: 개인 화물과 상점 판매 루프

목표: 행성에서 개인 화물을 수집하고 다른 행성에서 판매하는 보조 수입 루프를 만든다.

구현 범위:

- 개인 화물 데이터는 등급, 크기, 기본 판매가, 출발 행성 특성, 목적지 행성 특성 보정을 가진다.
- 등급은 `평범`, `희귀`, `특급`으로 시작한다.
- 개인 화물 크기는 창고 운송 점수와 적재 가능량에 반영한다.
- 행성 개인 화물 수집소 UI를 정비 화면 안의 진입점으로 추가한다.
- 상점 판매 탭에서는 개인 화물만 판매 가능하게 한다.
- 의뢰 화물은 판매할 수 없고 직접 납품 상호작용도 만들지 않는다.
- 행성 특성에 따른 판매가 보너스와 디메리트를 원본 표 기준으로 적용한다.

검증:

- 개인 화물 적재 가능성 EditMode tests
- 판매가 보정 tests
- 상점 판매 smoke
- Phase18 반복 루프 회귀

완료 기준:

- 개인 화물이 정산과 별개인 상점 판매 수입원이 된다.
- 의뢰 화물과 개인 화물의 규칙이 UI와 로직에서 분리된다.

## 5단계: 정비와 화물선 업그레이드 상세

목표: 행성 정비를 수리, 업그레이드, 장비 배치의 중심 화면으로 확장한다.

구현 범위:

- 수리비는 원본 `정산 정리` 문단 기준을 따른다: 6구역 전체 결손 내구도 합산 1%당 5달러.
- 6구역이 모두 0%인 상태는 일반 수리비가 아니라 총파손 비용 5000달러로 분리한다.
- 일반 수리비 상한은 `599 x 5 = 2995`달러로 둔다.
- 동력실 0% 견인 비용은 운송 중 견인 횟수별로 계산한다.
- 화물선 업그레이드 카테고리는 `구역 내구도 증가`, `화물선 무기 성능 업그레이드`, `자동 항법 강화`, `비품실 장비 슬롯 증가`, `화물선 내부 통제 강화`다.
- 업그레이드 비용은 원본 기준을 따른다:
  - 구역 내구도 증가: `$1000/$2000/$4000`
  - 화물선 무기 성능 업그레이드: `$1500/$2500/$4500`
  - 자동 항법 강화: `$3000/$4800/$6500`
  - 비품실 장비 슬롯 증가: `$1000/$2500/$5000`
  - 화물선 내부 통제 강화: `$2500/$5000/$10000`
- 구역 내구도 증가는 구매 즉시 적용한다.
- 무기 성능, 자동 항법, 비품실 슬롯, 내부 통제 강화는 구매 상태와 장착 상태를 분리한다.
- 화물선 외형 꾸미기는 데이터/진입점만 준비하고 최종 비주얼은 아트 패스에서 구현한다.

검증:

- 수리비, 총파손, 견인비 EditMode tests
- 업그레이드 구매/장착 tests
- 정비 화면 smoke
- Windows 개발 빌드

완료 기준:

- 정비 단계에서 손상, 비용, 업그레이드, 출발 가능 여부가 한 흐름으로 이어진다.
- 기존 Phase10/Phase18 정비 루프가 깨지지 않는다.

## 6단계: 6구역 손상 효과 상세 연동

목표: 원본 기획서의 6구역 손상 단계가 실제 운송, UI, 위험, 침입자 규칙에 영향을 주게 한다.

구현 범위:

- 조종실 손상:
  - 75% 이하: 조종에 따른 화물선 이동속도 감소.
  - 50% 이하: 자동 운전모드 꺼짐.
  - 25% 이하: 방향 전환 입력 감지 지연시간 증가.
  - 0%: 조종 불가, 운송 주행 시간 100% 추가 증가, 출발 불가.
  - 조종실 내구도 0% 도달 시 조종대 폭파와 근처/조종 중 유저 피해를 별도 폭발 피해 profile로 둔다.
- 운송창고 손상:
  - 75% 이하: 화물 적재 수량 `25+n%` 감소.
  - 50% 이하: 개인 화물 운송 불가, 화물 적재 수량 추가 감소.
  - 25% 이하: 화물 손실률 20%, 출발 불가.
  - 0%: 화물 손실률이 10초마다 1%씩 증가, 바닥 구멍으로 이동 경로 축소와 화물 내구도 대폭 하락.
- 무기실 손상:
  - 75% 이하: 플라즈마 이온포 사용 불가, 자동 조준 시스템 off.
  - 50% 이하: 무기 포탑 수량 절반 off.
  - 25% 이하: 포탑 방향 전환 입력 감지 지연시간 증가.
  - 0%: 운행은 가능하나 무기 작동 불가.
  - 무기실 내구도 0% 도달 시 포탑 조종대 폭파와 근처 유저 피해를 적용한다.
- 동력실 손상:
  - 75% 이하: 운송 주행 시간 50% 증가, 동력실 제외 5구역 중 랜덤 2구역 암전, 복도 전체 암전.
  - 50% 이하: 운송 주행 시간 100% 추가 증가, 부스터 사용 불가, 추가 암전/기능 off.
  - 25% 이하: 모든 구역 암전, 동력실 제외 나머지 구역 기능 off, 운송 주행 시간 100% 추가 증가.
  - 0%: 화물선 주행 off, 보험사 우주선 견인, 의뢰 실패, 개인 화물 소실, 견인비 추가, 출발 불가.
- 통제실 손상:
  - 75% 이하: 복도 20% 폐쇄.
  - 50% 이하: 복도 50% 폐쇄, 통제실 제외 5구역 중 2구역 CCTV 불가, 침입 감지 시스템 off.
  - 25% 이하: 복도 90% 폐쇄, 통제실 제외 5구역 CCTV 불가, 화물 손상 경고 off.
  - 0%: 폐쇄 구역 개방, 외부/내부 침입 억제 시스템 off.
  - 외부 침입 억제 off는 외계 생명체 침입 수 200% 증가, 내부 억제 off는 내부 침입자 능력치 300% 상승으로 연결한다.
- 비품실 손상:
  - 75% 이하: 장비 보관 개수 3개 감소.
  - 50% 이하: 장비 보관 개수 2개 추가 감소, 장비 보관 보안 시스템 off.
  - 25% 이하: 장비 보관 불가, 장비 내구도 10 하락.
  - 0%: 비품실 폭파로 모든 구역 내구도 25% 감소, 장비 내구도 하락마다 장비 폭파 25% 확률.
  - 비품실 내부 유저 피해와 긴급 수리/수리 장치 사용 불가를 반영한다.
- HUD와 방 콘솔에는 손상 효과를 원본 수치 기준으로 읽기 쉽게 표시한다.

검증:

- 구역별 threshold EditMode tests
- 운송 중 손상 효과 smoke
- 방 콘솔/CCTV PlayMode smoke

완료 기준:

- 각 구역 손상 단계가 하나 이상의 실제 게임 규칙에 연결된다.
- 임시 수치가 있으면 문서에 표시되고, 원본 수치가 있는 항목은 원본을 따른다.

## 7단계: 비품창고, 인벤토리, 상점 구매 상세

목표: 플레이어 장비와 비품창고가 전투, 수리, 운송 준비의 자원 관리 축이 되게 한다.

구현 범위:

- 손에 들 수 있는 아이템 칸은 기본 3칸, 주머니 업그레이드 후 4칸이다.
- 비품창고 초기 저장칸은 3칸이며, 비품실 장비 슬롯 업그레이드에 따라 5/10/25칸으로 확장된다.
- 비품창고 탭은 `전체`, `무기`, `방호`, `치료`, `강화`, `기타`를 제공한다.
- 상점 구매 탭은 원본 분류를 따른다:
  - 공통 물품
  - 유명세 제한 상품
  - 특별 물품
  - 특별 강화 물품
- 구매품은 손 슬롯 또는 비품창고에 들어가는 규칙을 가진다.
- 장비 내구도, 버리기, 사용 쿨다운, 구매품 1% 처분 규칙을 추가한다.
- 개인 화물 판매는 구매품 처분과 UI/로직에서 분리한다.

검증:

- 인벤토리 슬롯과 비품창고 tests
- 상점 구매/보관/처분 tests
- 장비 내구도 tests
- 장비 UI smoke

완료 기준:

- 운송 전 준비한 물품이 운송 중 접근 가능한 상태로 유지된다.
- 상점 판매 탭의 개인 화물 판매와 구매품 처분 규칙이 충돌하지 않는다.

## 8단계: 무기, 방호, 치료, 강화, 기타 아이템 1차

목표: 원본 기획서의 핵심 아이템 카테고리를 전투와 생존 루프에 연결한다.

구현 범위:

- 무기는 원본 명칭과 순서를 따른다: `막대기`, `머스켓`, `샷건`, `미니 화염방사기`, `전류봉`, `단검`.
- 방호 물품은 `제압 방패`, `타격 방호복`, `참격 방호복`, `절연복`, `방염복`, `얼굴 보호대`, `방탄 보호복`을 데이터화한다.
- 치료 물품은 `부상 완화제`, `지혈제 및 붕대`, `보조 배터리`, `보호막 충전 배터리`, `보호막 전환기`를 데이터화한다.
- 강화 물품은 `이속 강화제`, `근력 강화제`, `방호 강화제`, `신경 집중 강화`, `무기 증폭제`, `보호막 폭주 유도장치`를 데이터화한다.
- 기타 물품은 `청소기`, `휴대용 스피커`, `홀로그램 스프레이`, `섬광탄`, `연막탄`, `손전등`, `임시 개방 장치`, `긴급 수리 장치`, `임시 해킹 장치`를 데이터화한다.
- 특별 물품은 `기척 감지기`, `광선검`, `전류 지뢰`, `복도 정화 장치`, `적외선 시야경`이며 해금 전 구매 불가 상태로 유지한다.
- 특별 강화 물품은 `물리 방호복`, `나노머신 치료제`, `급속 보호막 완충제`, `수리 장치`이며 해금 전 구매 불가 상태로 유지한다.
- 1차 구현에서는 모든 아이템의 최종 모션을 만들지 않는다. 사용 조건, 결과, 소모 여부, 내구도 변화, 잠금 상태를 우선 만든다.

검증:

- 무기별 피해량과 사거리 tests
- 방호/치료/강화 효과 tests
- 아이템 사용 입력 smoke
- 침입자 전투 회귀 smoke

완료 기준:

- 각 아이템 카테고리가 최소 1개 이상의 실제 사용 가능한 물품을 가진다.
- 특별 물품과 특별 강화 물품은 해금 전 구매 불가 상태로 유지된다.

## 9단계: 플레이어 전투와 상태 이상

목표: 침입자와의 전투가 단순 체력 차감에서 원본 상태 이상, 보호막, 장비 효과를 포함한 생존 판단으로 확장된다.

구현 범위:

- 상태 이상은 원본 기준 7종만 사용한다: `정지`, `화상`, `출혈`, `탈진`, `피로`, `현기증`, `혼란`.
- 정지:
  - 지속시간 동안 행동 및 이동 불가.
  - 시전 중인 모션과 행동 중인 모션을 끊을 수 있다.
  - 전류봉, 전류 지뢰, 복도 정화 장치, 일부 적 공격과 연결한다.
- 화상:
  - 지속시간 동안 `n초당 m 피해`를 부여한다.
  - 미니 화염방사기, 방염복, 복도 정화 장치와 연결한다.
- 출혈:
  - 지속시간 동안 `n초당 m 피해`를 부여한다.
  - 원본 기준 2초 이상 공격이 비는 시간 없이 5초 이상 피격 시 발생한다.
  - 지혈제 및 붕대가 출혈을 해제한다.
- 탈진:
  - 지속시간 동안 이동속도 80% 감소, Shift 대시 불가.
  - 이속 강화제 종료 부작용과 연결한다.
- 피로:
  - 이동속도 30% 감소.
  - 원거리 무기 딜레이를 10초로 변경.
  - 근접무기 공격 속도 50% 감소 및 연사 딜레이 5초로 변경.
  - 근력 강화제 종료 부작용과 연결한다.
- 현기증:
  - 시야 흔들림, 화면 가장자리 검은 효과, 이동속도 50% 감소.
  - 신경 집중 강화 종료 부작용과 연결한다.
- 혼란:
  - 행동 불가, 이동 가능, 이동속도 70% 감소.
  - 섬광탄과 연결한다.
  - 칸타빌레, 아첼레란도, 콘 스피리토처럼 시야에 의존하지 않는 특정 개체는 혼란 면역을 가질 수 있다.
- 플레이어 피해는 보호막, 체력, 방호복, 원본의 “보호막에는 두 배로 적용” 특례를 profile로 분리한다.
- 무기와 적 공격은 원본에 명시된 상태 이상만 부여한다.
- 방호복과 치료/강화 물품은 원본 효과 범위 안에서 상태 이상에 영향을 준다.
- 사망자 수, 생존자 0명 클리닝 비용, 생명 보험 비용은 정산 입력으로 이어지게 한다.

검증:

- 피해와 보호막 적용 EditMode tests
- 상태 이상 발생/해제 tests
- 장비별 상태 이상 대응 tests
- 전투 PlayMode smoke
- 정산 비용 회귀 tests

완료 기준:

- 플레이어 피해, 사망, 정산 비용이 하나의 상태 모델로 이어진다.
- 상태 이상이 UI와 전투 결과에 원본 명칭으로 반영된다.

## 10단계: 조종실, 무기실, 통제실 운용 고도화

목표: 운송 중 플레이어가 어떤 방에서 어떤 시스템을 조작할지 판단할 선택지를 늘린다.

구현 범위:

- 조종실 수동 운행을 위험 구간 회피, 부스터, 자동 운행 전환과 연결한다.
- 부스터 사용은 위험 구간 지속시간 감소와 동력실 손상 제한을 반영한다.
  - 소행성 지대, 화물 자유 연대, 외계 생명체 구역은 수동 조종 중 부스터 사용 시 지속시간 10초 감소.
  - 우주 해적 구역은 수동 조종 중 부스터 사용 시 지속시간 45초 감소.
  - 은폐 블랙홀은 별도 방향 판정과 부스터 탈출 조건이 필요하며, 사용자 확인에 따라 후반 위험 확장으로 미룬다.
  - 부스터 입력 키는 원본에 명시되지 않았으므로 임의 키 바인딩을 만들지 않는다. 먼저 순수 규칙/API와 검증 경로를 연결하고, 실제 입력은 사용자 확인 후 추가한다.
- 무기실 자동 포탑과 수동 포탑을 분리한다.
  - 수동 운행 모드 중에는 무기실 이용 불가이며, 무기실은 자동 조준 및 발사 모드로 강제 전환한다.
- 무기실 플라즈마 포 업그레이드, 쿨다운, 우클릭 발사를 추가한다.
  - 화물선 무기 성능 업그레이드는 탄창 수를 `50 -> 60 -> 75 + 플라즈마 포 배치 -> 100` 순서로 확장한다.
  - 플라즈마 포는 수동 포탑 모드에서 마우스 우클릭으로 발사하며, 3초간 지속, 0.1초당 데미지 50, 쿨타임 1분이다.
  - 플라즈마 포 쿨타임은 자동 모드일 때도 회복된다.
- 통제실 CCTV 화면을 구역 상태, 침입자 감지, 화물 상태 경고와 연결한다.
  - 대형 스크린 기본 CCTV 순서는 조종실 -> 운송창고 -> 동력실 -> 무기실 -> 비품실(CCTV 존재할 시) -> 조종실이다.
  - 통제실 손상도 50% 이하는 통제실 제외 5구역 중 2구역 CCTV 사용 불가, 25% 이하는 통제실 제외 5구역 CCTV 사용 불가를 반영한다.
- 통제실 대형 스크린과 세로형 스크린의 전환, 구역 임시 폐쇄, 내부 정화 시스템을 원본 기준으로 구현한다.
  - 대형 스크린에서 마우스 우클릭 시 세로형 스크린으로 전환한다.
  - 세로형 스크린의 구역 나열 순서는 조종실, 운송창고, 비품실, 동력실, 통제실, 무기실이다.
  - 세로형 스크린에서 클릭한 해당 구역만 임시 폐쇄하고 30초 동안 내부 정화 시스템을 발동한다.
  - 내부 정화 시스템은 폐쇄한 구역 사방에 화염을 일으키며 총 화염 데미지는 500이다. 구역 안의 플레이어도 같은 피해 대상이다.
  - 이 시스템 자체로 구역 내구도 손실은 발생하지 않는다. 가연성 물품/폭발성 물질로 인한 별도 손상은 해당 물품/폭발 시스템 구현 단계에서 연결한다.
  - 작동 종료 시 해당 구역 임시 폐쇄를 해제하고 개방한다.
  - 통제실 내부 정화 시스템은 특수 물품 `복도 정화 장치`와 별개다. `복도 정화 장치`는 모든 복도 구역을 대상으로 하며 특수 물품/특별 의뢰 단계에서 별도 구현한다.
- 통제실 손상도에 따라 CCTV, 폐쇄, 정화 기능이 제한된다.

검증:

- 조종/부스터 rules tests
- 자동/수동 포탑 tests
- 통제실 폐쇄/정화 tests
- 방 운용 PlayMode smoke

완료 기준:

- 조종실, 무기실, 통제실이 서로 다른 대응 수단을 제공한다.
- 구역 손상 상태가 방 운용 기능을 실제로 제한한다.

## 11단계: 외부 위험 구간 확장

목표: 소행성 지대 하나에서 출발한 외부 위험을 원본의 주요 위험 구간으로 확장한다.

구현 범위:

- 소행성 지대는 `크기 小`, `크기 大`를 분리한다.
  - 출몰 시 10초~2분 지속.
  - 자동 조종 + 자동 포탑 상태에서는 5초마다 70% 확률로 랜덤 구역 내구도 감소.
  - 크기 小는 내구도 10% 감소, 크기 大는 20% 감소.
  - 수동 포탑 대상 체력은 크기 小 400, 크기 大 1000.
  - 수동 조종 부스터는 구역 지속시간 10초 감소.
  - 발생 확률은 운행 중 5초마다 30%.
- 화물 자유 연대 출몰 지역:
  - 5초~35초 지속.
  - 자동 조종 + 자동 포탑 상태에서 2초마다 70% 확률로 침입.
  - 수동 조종 부스터는 지속시간 10초 감소.
  - 발생 확률은 운행 중 10초마다 15%.
  - 유명세 1800 미만이면 발생하지 않는다.
- 우주 해적 출몰 지역:
  - 1분~5분 지속.
  - 침입선 접근과 포격을 동시에 다룬다.
  - 자동 조종 + 자동 포탑 상태에서 5초마다 90% 침입, 30% 포격.
  - 포격 피격 시 랜덤 구역 내구도 20% 감소.
  - 수동 조종 부스터는 지속시간 45초 감소.
  - 발생 확률은 운행 중 10초마다 5%.
  - 유명세 3000 미만이면 발생하지 않는다.
- 외계 생명체 출몰 구역:
  - 30초~5분 지속.
  - 자동 조종 + 자동 포탑 상태에서 3초마다 80% 확률로 침입.
  - 수동 조종 부스터는 지속시간 10초 감소.
  - 발생 확률은 운행 중 5초마다 10%.
  - 유명세 900 미만이면 발생하지 않는다.
- 은폐 블랙홀:
  - 발생 확률은 운행 중 10초마다 0.5%.
  - 자동 조종 모드로는 벗어날 수 없다.
  - 너무 가까워지면 화물선 전체 내구도 100% 감소와 내부 선원 사망 처리.
  - 수동 조종 모드에서 빨려 들어가는 방향을 파악하고 반대/탈출 방향으로 부스터를 사용해야 벗어날 수 있다.
  - 유명세 4500 미만이면 발생하지 않는다.
  - 사용자 확인에 따라 11단계 구현 대상에서 제외하고 후반 위험 확장으로 미룬다.
- 위험 구간 유명세 조건은 현재 유명세의 반복 차단 조건이 아니라 세션 단위 해금 조건이다.
  - 해당 세션에서 한 번 기준을 돌파한 위험 구간은 이후 유명세가 기준 아래로 내려가도 계속 발생할 수 있다.
  - 게임오버로 인한 초기화 때만 위험 구간 해금 상태를 초기화한다.

검증:

- 위험 구간 스케줄 EditMode tests
- 소행성 크기별 결과 tests
- 각 위험 구간 대응 smoke

완료 기준:

- 외부 위험이 침입선, 포격, 침입자 발생, 구역 손상 중 하나 이상으로 이어진다.
- 위험 구간 유명세 해금 상태가 세션 안에서 유지되고, 유명세 하락으로 재잠금되지 않는다.
- 은폐 블랙홀은 원본 수치와 유명세 조건을 문서에 유지하되, 11단계 구현에서는 제외한다.

## 12단계: 침입자 AI 공통 프레임워크 완성

목표: 여러 적대 세력을 추가하기 전에 침입자 이동, 목표 선택, 공격, 구역 영향, 세력 관계를 공통화한다.

상태: 구현 완료.

구현 범위:

- 침입자 목표 유형은 원본의 큰 분류를 따른다: 운송 화물 공격, 화물선 공간 점유, 플레이어 공격, 화물선 파괴.
- 방과 복도 이동 경로를 침입자 AI가 사용할 수 있게 한다.
- 구역 폐쇄, 암전, CCTV, 억제 시스템이 침입자 이동과 능력치에 영향을 주게 한다.
- 적대 세력은 `씨앗체`, `외계 생명체`, `화물 자유 연대`, `해적`으로 분리한다.
- 관계 모델은 원본의 `적대`, `경쟁`, `동맹`, `유대`, `지휘`를 표현한다.
- 침입자 시각 표현은 placeholder에서 시작하되 식별 가능한 형태와 HUD 신호를 제공한다.

검증:

- 목표 선택 EditMode tests
- 구역 이동과 폐쇄 영향 tests
- 세력 관계 tests
- 침입자 PlayMode smoke

완료 기준:

- 새 침입자 타입을 추가할 때 공통 모델을 재사용할 수 있다.
- 기존 Parvum 동작이 공통 프레임워크 위에서 회귀 통과한다.

## 13단계: 씨앗체 상세 구현

목표: Parvum 1종에서 씨앗체 세력의 대표 행동과 금속/화물선 상호작용을 확장한다.

구현 범위:

- 씨앗체 원본 분류는 사용자 확인에 따라 `파르붐`, `푸가`, `롱가 아르마`, `테르고`, `우르제레`, `소치에타스`, `몬스트룸`, `미메시스`다.
- 파르붐은 금속을 1순위로 노리고, 방치 시 해당 구역 내구도를 감소시킨다.
- 파르붐은 생체 대상 기준 0.5초당 6 피해, 0.8초간 이속 감소 30%를 부여한다. 보호막이 있으면 피해와 이속 감소 규칙이 달라진다.
- 푸가는 비행 개체로 금속 섭취와 구역 손상을 다룬다.
- 롱가 아르마는 긴 팔과 3~4 사거리 구역/대상 공격을 구현한다.
- 테르고는 유저 후방 접근, 꿰뚫기, 자세 무너짐 상태 이상을 구현한다. 자세 무너짐은 원본 7종 상태 이상과 별개인지 사용자 확인 후 모델링한다.
- 우르제레는 해당 구역 씨앗체 강화와 비씨앗체 시야 감소를 구현한다.
- 소치에타스는 군집 행동, 금속 목표, 생체 대상 이속 감소 50%를 구현한다.
- 몬스트룸은 대형 금속 위협, 구역 내 전체 개체 이동속도 80% 감소 효과를 구현한다.
- 미메시스는 유저 외형 변신과 유저 고정 목표를 구현한다.
- 미메시스의 목소리 저장/흉내 기능은 원본 기능으로 남기고, 싱글 플레이 축소 구현 여부는 사용자 확인 후 결정한다.
- 씨앗체는 외부에서 침입 저지가 불가능하고 내부 처리 위주로 다룬다.

검증:

- 씨앗체별 데이터 tests
- 금속/구역 목표 행동 tests
- 씨앗체 관계 tests
- 씨앗체 침입 smoke

완료 기준:

- 씨앗체는 단순 체력 차이만이 아니라 목표와 대응 방식이 구분된다.
- 원본 내부 명칭 상충 항목은 사용자 확인 없이는 확정하지 않는다.

## 14단계: 외계 생명체 상세 구현

목표: 외계 생명체 출몰 구역과 침입자를 씨앗체와 다른 위협으로 만든다.

구현 범위:

- 외계 생명체 타입은 원본 기준 `칸타빌레`, `콘 스피리토`, `아첼레란도`, `그라베`, `스모르찬도`, `오스티나토`, `돌로레`다.
- 외계 생명체는 외부에서 무기실 포탑으로 침입 저지가 가능하다.
- 칸타빌레는 소리 목표, 음파 정지, 동력실 공명을 구현한다.
- 콘 스피리토는 돌진 반복, 목표 없음, 특정 개체군 조우 시 돌진을 구현한다.
- 아첼레란도는 조우 시간이 길어질수록 이동속도/공격속도 상승을 구현한다.
- 그라베는 상태 이상 피해 1.5배와 상태 이상 지속시간 2배 특성을 구현한다.
- 스모르찬도는 설치형 액체, 흡수당함 스택, 정지, 촛불/좀비 형태 전환을 구현한다.
- 오스티나토는 폭주 모드와 휴식/회복 패턴을 구현한다.
- 돌로레는 액자 형태, 체력 40% 이하 대상 끌고감 즉사 판정을 구현한다.
- 외계 생명체는 같은 분류군끼리 동맹, 씨앗체와 적대, 나머지와 경쟁 관계를 반영한다.

검증:

- 외계 생명체 타입별 rules tests
- 출몰 구역 침입 tests
- 세력 관계 tests
- 대표 외계 생명체 smoke

완료 기준:

- 외계 생명체는 침입 빈도, 상태 이상, 외부 접근 방식에서 씨앗체와 구분된다.
- 모든 타입을 한 번에 완성하지 못하더라도 최소 2종 이상이 식별 가능한 위협으로 동작한다.

## 15단계: 화물 자유 연대 상세 구현

목표: 화물 자유 연대를 화물 탈취 목적의 기계형 침입 세력으로 구현한다.

구현 범위:

- 화물 자유 연대는 `니게티프`, `리벨리온`, `레지스탕스`, `레볼루션`으로 분리한다.
- 화물 자유 연대는 침입선을 통해 침입하며, 침입선은 무기실 포탑으로 격추 가능하다.
- 니게티프는 운송 중인 화물 공격, 주머니 저장, 제거 시 화물 드랍을 구현한다.
- 리벨리온은 화물 보호막 설치와 이후 화물선/유저 공격 전환을 구현한다.
- 레지스탕스는 비품실 우선 목표, 무기 탈취, 제거 시 탈취 장비 드랍을 구현한다.
- 레볼루션은 비품실 폭탄 설치, 비품실 0% 패널티 유발, 이후 다른 구역 공격을 구현한다.
- 침입선 체력, 크기, 탑재 수량, 정면 마크는 원본 수치를 데이터화한다.
- 화물 자유 연대는 외계 생명체와 경쟁, 씨앗체/해적과 적대 관계를 반영한다.

검증:

- 침입선 접근/격추 tests
- 화물 공격/보호막 tests
- 무기 탈취/드랍 tests
- 특수 의뢰 드랍 조건 tests
- 화물 자유 연대 smoke

완료 기준:

- 화물 자유 연대는 단순 전투원이 아니라 화물 탈취/보호막/사보타주 목적을 가진 세력으로 동작한다.
- 특수 의뢰의 선행 조건에 필요한 처치/드랍 이벤트를 제공한다.

## 16단계: 우주 해적 상세 구현

목표: 해적을 고위험 구역, 침입선, 포격, 지휘관 행동으로 구성된 후반 위협으로 만든다.

구현 범위:

- 해적은 `파후르`, `쿠르사`, `이슈판트`, `아타`로 분리한다.
- 해적 출몰 구역의 지속 시간, 포격, 침입 확률을 구현한다.
- 해적 침입선 타입, 체력, 크기, 탑재 유닛, 정면 마크를 데이터화한다.
- 파후르는 미니 화염방사기 기반 구역/유저 공격을 구현한다.
- 쿠르사는 제압방패, 방어 태세, 밀치기, 방패 내구도를 구현한다.
- 이슈판트는 머스켓과 장검을 사용하는 소수 정예 병사로 구현한다.
- 아타는 지휘관으로 수호태세와 돌파태세를 지시한다.
- 아타의 구역별 사보타주를 구현한다: 동력 출력 감소, 통제실 해킹, 자동 조종 무력화, 포탑 비활성화, 비품실/운송창고 폭탄 설치.
- 아타 사망 시 나머지 해적 소속 개체 정지 규칙을 구현한다.
- 해적은 외계 생명체와 경쟁, 화물 자유 연대/씨앗체와 적대 관계를 반영한다.

검증:

- 해적 구역 rules tests
- 포격과 침입선 tests
- 아타 지휘/사보타주 tests
- 해적 침입 smoke

완료 기준:

- 해적은 포격, 침입, 사보타주가 결합된 고위험 세력으로 동작한다.
- 조종실, 통제실, 무기실, 동력실의 상세 구현과 상호작용한다.

## 17단계: 특수 의뢰와 해금 루프

목표: 유명세, 행성 방문, 적 처치, 특정 운송 성공을 장비 해금과 연결한다.

구현 범위:

- 특수 의뢰 조건 모델은 유명세, 행성 특성 방문 횟수, 난이도 완료 횟수, 특정 적 처치 횟수, 특정 아이템 회수를 가진다.
- 기척 감지기 해금:
  - 조건: 유명세 500 이상, 유기체가 많은 행성 1회 이상 방문.
  - 의뢰: 화물 자유 연대 레지스탕스 2개체와 레볼루션 1개체 처치 및 칩 회수.
  - 보상: 기척 감지기 구매 해금, 특별 의뢰 수당 2000달러.
- 광선검 해금:
  - 조건: 유명세 1000 이상, 화산 활동 활발 행성 3회 이상 방문, 매우 어려움 의뢰 2회 이상.
  - 의뢰: 이슈판트 동력장치, 아타 조절 장치 회수.
  - 보상: 광선검 1개, 특별 의뢰 수당 2500달러.
- 전류 지뢰 해금:
  - 조건: 유명세 3000 이상, 기본 광물 풍부 행성 1회 이상 방문, 희귀 광물 풍부 행성 1회 이상 방문, 레볼루션 3개체 이상 처리.
  - 의뢰: 창고 반 이상을 차지하는 특정 물품 운송, 해당 물품 내구도 55% 이상 유지.
  - 보상: 특정 행성 상점에서 전류 지뢰 구매 해금, 특별 의뢰 수당 3000달러.
- 복도 정화 장치 해금:
  - 조건: 유명세 5000 이상, 몬스트룸/돌로레/레볼루션/아타 각각 1회 이상 처치.
  - 의뢰: 4분 44초 고정 항로 운송, 전체 구간 침입 발생 구간, 침입 확률 3배.
  - 보상: 정비소 복도 정화 장치 지급 및 설치 상태 업그레이드, 특별 의뢰 수당 7500달러.
- 의뢰 실패 시 유명세를 제외한 나머지 조건을 초기화한다.
- 특수 의뢰 화물도 직접 납품 상호작용 없이 목적지 도착 정산에서 자동 처리한다.

검증:

- 특수 의뢰 조건 tests
- 처치/회수 tests
- 정산 자동 완료 tests
- 특수 의뢰 smoke

완료 기준:

- 적 처치와 운송 성공이 장비 해금으로 이어진다.
- 특수 의뢰도 직접 납품 상호작용 없이 정산에서 처리된다.

## 18단계: 행성 내 화면과 UX 완성도

목표: 정비, 의뢰, 상점, 개인 화물, 업그레이드가 행성 체류 흐름으로 자연스럽게 이어지게 한다.

구현 범위:

- 행성 화면에서 정비소, 의뢰소, 상점, 개인 화물 수집소 진입 흐름을 정리한다.
- 행성 맵은 상점, 수리소, 우주선, 화물 공급소를 표시한다.
- 의뢰 게시판은 협회, 개인, 특수 의뢰를 구분해서 보여준다.
- 상점은 구매 탭과 판매 탭을 명확히 분리한다.
- 정비 화면은 수리, 업그레이드, 배치, 출발 가능 여부를 통합해서 보여준다.
- 튜토리얼 이후 스킵 버튼과 1100달러 지급 조건을 구현한다. 금액은 튜토리얼 고정 보상 1000달러와 수리 지원 100달러의 합계다.
- 협회 가입 계약서 자동 스크롤, 아래 방향키 빠른 이동, `Ctrl+C` 정지 후 `Ctrl+X` 개인 사업자 시작 루트는 원본 기준으로 이 단계에서 구현한다.
- 이미 잠정 동의한 상태에서 `아니오` 버튼이 눌리지 않는 흐름을 원본 기준으로 구현한다.

검증:

- 행성 화면 PlayMode smoke
- 의뢰/상점/정비 UI 회귀 smoke
- 텍스트 겹침과 버튼 상태 수동 체크리스트

완료 기준:

- 운송 종료 후 다음 운송 준비까지 필요한 주요 행동이 행성 화면에서 가능하다.
- 히든 루트는 원본 조건 그대로 구현되고, 임의 UX로 바뀌지 않는다.

## 19단계: 저장, 설정, 플랫폼 경계

목표: 상세 구현된 게임 상태를 세션 간 유지하고 Steam 출시 준비를 위한 경계를 단단하게 만든다.

구현 범위:

- 저장 대상은 플레이어 장비, 비품창고, 화물선 상태, 업그레이드, 유명세, 협회 상태, 특수 의뢰 진행도, 방문 행성 기록이다.
- 튜토리얼 완료 여부와 스킵 가능 여부를 저장한다.
- 설정 저장 대상은 해상도, 음량, 마우스 감도, 접근성 후보로 둔다.
- 업적, 클라우드, Steam 통계는 인터페이스만 준비하고 실제 SDK 연결은 하지 않는다.
- 저장 파일 버전과 마이그레이션 정책을 둔다.

검증:

- 저장/로드 EditMode tests
- 버전 마이그레이션 tests
- 새 게임과 이어하기 smoke
- Windows 개발 빌드

완료 기준:

- 플레이테스트 중 반복 진행한 결과가 저장되고 복구된다.
- 게임 로직이 플랫폼 SDK를 직접 참조하지 않는다.

## 20단계: 아트, 사운드, 연출, 레벨 완성도

목표: graybox와 placeholder를 플레이 가능한 수준으로 단계적으로 교체한다.

구현 범위:

- 6구역과 복도 구조를 원본 묘사에 맞춰 다듬는다.
- 조종실 전면 유리, 동력실 도넛형 구조, 통제실 스크린 구성, 무기실 포탑 자리, 비품실 창고와 사출대, 운송창고 중심 화물 표현을 개선한다.
- 저채도, 어두운 조명, 제한된 시야, 위험 신호 사운드를 상세화한다.
- HUD 체력/보호막, 맵, 침입 신호, 구역 경고 연출을 다듬는다.
- 적대 개체 placeholder를 타입별 식별 가능한 모델 또는 임시 고품질 표현으로 교체한다.
- 성능 예산과 로딩 시간을 측정한다.

검증:

- 주요 씬 PlayMode smoke
- 시야, UI 겹침, 카메라 클립 수동 체크
- 성능 샘플링
- Windows 개발 빌드

완료 기준:

- 주요 방과 적대 타입이 플레이 중 식별 가능하다.
- 연출 추가 후에도 최신 기능 smoke가 통과한다.

## 21단계: 밸런싱과 플레이테스트 하드닝

목표: 상세 시스템을 포함한 싱글 플레이 루프를 반복 테스트 가능한 출시 후보 수준으로 안정화한다.

구현 범위:

- 의뢰 보상, 수리비, 위험 발생 확률, 침입자 체력과 피해량, 아이템 가격을 원본 수치 및 사용자 확인 사항과 대조한다.
- 원본 수치가 있는 항목은 밸런싱 명목으로 변경하지 않고, 원본에 없거나 플레이테스트 튜닝이 필요한 항목은 사용자 확인 후 조정한다.
- 의뢰 유형별 보상 구조와 난이도별 위험/보상 흐름이 원본 기준에 맞는지 확인한다.
- 초반 30분, 중반 반복 운송, 고위험 특수 의뢰 시나리오를 플레이테스트 항목으로 만든다.
- 실패 후 복구 가능성, 게임 오버 조건, 부채 유예 규칙을 재검증한다.
- 자동화 smoke를 최신 통합 루프 기준으로 정리한다.
- 플레이테스트 버그를 우선순위별로 triage한다.

검증:

- Harness validation
- EditMode tests
- 전체 통합 smoke 묶음
- Windows 개발 빌드
- 수동 플레이테스트 체크리스트

완료 기준:

- MVP 루프가 상세 시스템을 포함한 상태에서도 반복 가능하다.
- 온라인/멀티 구현 전 싱글 플레이와 로컬 상태 경계가 안정적이라는 근거가 남는다.

## 22단계: 온라인/멀티플레이 설계 게이트

목표: 최대 5인 온라인 멀티 구현을 시작하기 전에 권한 모델, 동기화 범위, Steam 연동 범위를 별도 설계한다.

구현 범위:

- 이 단계는 구현 단계가 아니라 설계 승인 단계다.
- 최대 5인 파티의 host authority 모델을 정의한다.
- 조종실, 무기실, 통제실, 비품창고, 정비/상점/의뢰 UI의 상호작용 소유권을 정한다.
- 위험 구간, 침입자, 정산, 사망자 수, 화물 손실, 방 손상은 authoritative session에서만 확정되게 한다.
- Steam lobby, invite, reconnect, late join, disconnect, migration 여부를 결정한다.
- 로컬 협동 상태 모델을 어떤 온라인 메시지로 매핑할지 결정한다.
- 네트워크 테스트 전략과 multi-instance 검증 방식을 정한다.

검증:

- 문서 리뷰
- 로컬 협동 foundation 회귀
- 네트워크 구현 전 위험 분석 체크리스트

완료 기준:

- 사용자가 온라인/멀티 설계를 별도로 승인한다.
- 승인 전에는 Steam 로비, 실제 네트워크 패키지, 최대 5인 동기화 구현을 시작하지 않는다.

2026-06-09 설계 게이트 산출물:

- `docs/MULTIPLAYER_DESIGN_GATE.md`에 host-authority 모델, 상호작용 소유권, authoritative sync 범위, Steam lobby/invite/reconnect/late join/disconnect/migration 정책, 로컬 협동 상태의 온라인 메시지 매핑, 네트워크 테스트 전략을 정리했다.
- 설계 문서 작성은 완료했지만, 실제 온라인 구현 시작은 해당 설계에 대한 사용자 구현 승인 이후로 제한한다.

## 사용자 확인 필요 항목

아래 항목은 구현 전에 사용자 확인이 필요하다.

- 씨앗체 상세 구현 순서. 기본 제안은 원본 목록 순서를 따른다.
- 테르고의 `자세 무너짐`, 파르붐/소치에타스의 `이속 감소`, 몬스트룸의 `이동속도 감소`를 원본 7종 상태 이상과 별도 전투 modifier로 둘지, 상태 이상 체계 안에 넣을지.
- 미메시스의 목소리 저장/흉내 기능을 싱글 플레이에서 어떤 placeholder로 둘지.
- 화물선 외형 꾸미기를 기능 중심 placeholder로 먼저 둘지, 아트 패스에서 본격 구현할지.
- 모든 적대 타입을 완성한 뒤 특수 의뢰를 구현할지, 필요한 대표 타입만 먼저 만들고 특수 의뢰를 병행할지.

4. 온라인/멀티는 22단계 설계 게이트 전까지 구현하지 않는다.
