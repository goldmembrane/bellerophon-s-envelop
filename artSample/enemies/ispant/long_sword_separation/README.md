# 이슈판트 장검 분리 검토 샘플

## 결과 구성

- `Ispant_LongSword_Separated_Sample.blend`: 원본 참조 메시와 분리된 본체·장검 오브젝트를 포함한 Blender 파일
- `Ispant_LongSword_Separated_Sample.fbx`: `Armature`, `Ispant_Body_Without_LongSword`, `Ispant_LongSword_Exact`를 포함한 검토용 FBX
- `Ispant_LongSword_Separated_Review.png`: 왼쪽 원본, 가운데 장검 분리 본체, 오른쪽 분리 장검 비교 렌더
- `Ispant_LongSword_Separation_Comparison.html`: 비교 이미지, 교정된 분리 수치, 산출물 링크와 Unity 적용 상태를 한 페이지에 정리한 요약 HTML
- `build_long_sword_separation.py`: 동일 분리와 검증을 반복하기 위한 제작 스크립트

## 분리 기준

원본 `char1` 메시 전체는 하나의 연결 요소이므로 `Separate by Loose Parts`로 장검만 자동 분리할 수 없었다. 최초 샘플에서 선택했던 17개 UV 섬·215면은 사용자가 지적한 대로 머스켓 일부였으므로 폐기했다. 그다음 19개 UV 섬·99면 결과는 사용자가 다시 지정한 검신만 포함하고 검자루가 빠진 불완전한 결과였으므로 다시 폐기했다.

세 번째 29개 UV 섬·242면은 원본에서 하나로 이어지는 장검 표면으로 분리됐다. 이후 칼자루로 추정해 더했던 17개 UV 섬·270면은 사용자 확인 이미지와 본 웨이트·연결 성분 진단 결과 실제 신체 면으로 판정됐다. 그중 16개 섬·242면은 왼쪽 허리·골반 표면이고, `U530` 28면은 왼쪽 전완 표면이다. 이 270면은 장검 선택에서 제외하고 원본 그대로 본체에 복구했다.

장검 제거 뒤 모션 자세에서 왼쪽 허벅지 안쪽 결손이 드러났다. 원본에는 장검 뒤를 덮는 왼쪽 다리 면이 없으므로 원본 면 복구만으로는 메울 수 없었다. 오른쪽 다리 원본을 좌우 다리 본에서 계산한 대칭축 `X=-0.691260815`로 반전하고, 기존 왼쪽 다리와의 거리가 `2.5`를 넘는 유일한 연결 성분을 결손 대응 영역으로 고정했다. 이 영역은 오른쪽 다리 원본 12면·13정점이며 왼쪽 허벅지 상단 범위에만 추가했다. 오른쪽 본 웨이트는 대응하는 왼쪽 본 이름으로 치환했고 UV와 머티리얼 면 배정은 원본 오른쪽 다리 값을 유지했다.

장검 242면은 원본 면을 그대로 별도 오브젝트로 분리했다. 장검 자체의 형태 보정·덮개 면·두께 보강은 하지 않았다. 장검 분리 경계는 46개 에지이며, 대칭 복구 패치는 12개 경계 에지를 갖는다.

## 수치

- 원본 FBX SHA-256: `7B682C49CDB2F4A563B736857E544DD7FCCD7213A5C375DEB92F56CE3A2E51B7`
- 원본: 4,980정점, 10,028면
- 장검 분리·왼쪽 다리 복구 본체: 4,895정점, 9,798면
- 분리 장검: 143정점, 242면
- 원본에서 복구한 신체: 122정점 증가, 270면 복구
- 오른쪽 다리 대칭 복구 패치: 13정점, 12면
- 다리 대칭축: `X=-0.691260815`
- 공유 경계: 46개 에지·45개 정점
- 장검 월드 경계 최소: `(0.195404, -0.150592, 0.174190)`
- 장검 월드 경계 최대: `(0.437851, 0.062338, 1.105124)`

분리 전 원본의 각 면이 분리 후 본체·장검에 모두 보존됐음을 좌표, UV, 버텍스 그룹 웨이트, 면 방향, 면별 머티리얼 배정의 결합 서명으로 확인했다. 추가된 서명은 대칭 복구 패치 12면뿐이다. 두 오브젝트의 머티리얼 슬롯도 원본과 동일하다. 내보낸 FBX를 Blender에 다시 가져와 본체 4,895정점·9,798면, 장검 143정점·242면 및 패치 12면의 좌표·UV·웨이트·면 방향을 재확인했다.

## 적용 상태

사용자 지시에 따라 신체 270면과 왼쪽 다리 대칭 패치 12면을 포함한 본체를 Unity 직접 원본 `Assets/_Project/Art/Enemies/Ispant/Models/Ispant_New_Direct_Source.fbx`에 적용했다. 출력 SHA-256은 `E5A1067392ACE8009782E886202C4F2670B57741DC8A33BDA7D06410FFC71A5F`다. `.meta`와 `CargoRunMvp.unity`는 수정하지 않았고, 동일 GUID를 참조하는 기존 배치 12개에 FBX 임포트 결과가 반영된다.
