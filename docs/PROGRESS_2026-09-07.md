## 편집 상태 SceneView 이동 성능 원인 확인 및 자동 갱신 수정

- 초기 실제 전경 SceneView 이동 기록에서 약 `8ms ↔ 41ms`의 교대 갱신을 확인했다. 긴 갱신에서 Scene 렌더 CPU 시간이 비례해 증가하지 않고 렌더 스레드의 메인 스레드 명령 대기가 증가했다. 당시에는 원인을 확정하지 않고 프레임 진행·대기 경로의 전체 CPU 조사로 범위를 좁혔으며, 아래 A/B/A 비교에서 원인 확인에 도달했다.

- 상세 근거는 `docs/validation/scene_view_performance_2026-09-07/actual_navigation_analysis.md`에 기록했다. 진단용 CPU 타임라인 수집 도구와 브리지 명령을 추가했으며, 첫 전체 CPU 기록은 비활성 에디터 자료여서 실제 이동 지연의 원인 근거에서 제외했다.
