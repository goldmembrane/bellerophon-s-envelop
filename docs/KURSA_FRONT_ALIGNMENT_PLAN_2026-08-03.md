# 쿠르사 몸통·양팔·얼굴 정면 정렬 분석 및 작업 계획

- 작성일: 2026-08-03
- 대상 씬: `Assets/_Project/Scenes/CargoRunMvp.unity`
- 대상 루트: `Approved Kursa Enemy Placement`
- 대상 모델: Unity에 배치된 쿠르사 12개
- 현재 상태: 분석 및 계획 수립 완료, 모델·씬·애니메이션 미수정

## 1. 판정 기준

이번 분석의 우선순위는 다음과 같다.

1. 사용자가 제공한 현재 Unity 화면과 사용자의 직접 시각 판정
2. 원본 정면 이미지 `image/KUŠkursa(쿠르사).png`
3. 현재 씬·런타임 FBX·애니메이션에 직렬화된 실제 상태
4. 기존 검사 기록과 수치

기존 검사 결과가 현재 화면과 충돌하면 기존 `PASS`를 완료 근거로 사용하지 않는다. 특히
얼굴 방향 `0.05595291도` 기록은 실제 얼굴판 방향을 측정한 값이 아니므로 현재 얼굴 정면
판정에서 무효다.

## 2. 원본에서 확인되는 목표 자세

원본 정면 이미지는 다음 조건을 동시에 만족한다.

- 흉곽과 복부 장갑의 좌우 중심이 수직 중심선을 공유한다.
- 양쪽 어깨 외형이 정면에서 자연스러운 높이와 폭으로 연결된다.
- 방패가 없는 오른팔은 실제 오른쪽 어깨 소켓에서 시작해 몸통 옆으로 거의 수직으로
  내려오며, 팔꿈치와 손목에는 작은 자연 굴곡이 있다.
- 방패 팔은 실제 왼쪽 어깨 소켓에서 시작해 방패 손잡이로 이어지고, 방패는 몸 앞쪽에서
  세로로 선다.
- 이마판, 양쪽 눈구멍, 코 융기, 턱 끝이 하나의 수직 중심선을 이루고 얼굴판이 정면을
  향한다.

따라서 목표는 본 축을 보기 좋게 맞추는 것이 아니라, 정면 카메라에서 실제 메시의 몸통·
어깨 소켓·팔·얼굴판이 위 조건을 만족하게 만드는 것이다.

## 3. 현재 몸통 분석

현재 복구된 정적 자세의 본 끝점으로 계산한 값은 다음과 같다.

| 항목 | 현재 값 | 해석 |
| --- | ---: | --- |
| 좌우 어깨선의 수평면 비틀림 | 약 `1.966도` | 몸통 자체의 좌우 회전은 작다. |
| 좌우 어깨선의 기울기 | 약 `4.858도` | 양 어깨 높이가 정면 기준으로 기울어 있다. |
| `Spine01` 좌우 기울기 | 약 `0.803도` | 좌우 쏠림은 작다. |
| `Spine01` 전후 기울기 | 약 `7.062도` | 전방 기울기는 있지만 정면을 사선으로 보는 주원인은 아니다. |

결론은 몸통 전체가 크게 돌아간 상태라기보다, 소폭의 어깨선 기울기와 전방 기울기가 있는
상태다. 몸통을 큰 각도로 통째로 회전하면 오히려 현재 정면에 가까운 흉곽을 망가뜨릴 수
있다. 몸통은 흉갑·복부 장갑의 실제 좌우 대응점으로 미세 조정하고, 팔 문제는 팔 체인에서
별도로 해결해야 한다.

## 4. 현재 양팔 분석

### 4.1 방패 없는 오른팔

현재 런타임 생성 기록은 오른팔이 복구된 소스 자세 그대로임을 명시한다.

- 변경된 오른팔 정점: `0`
- 오른팔 바깥쪽 추가 이동값: `0`
- 오른팔 체인의 변경된 rest bone: 없음
- 상완의 아래쪽 기준 각도: 약 `74.706도`
- 전완의 아래쪽 기준 각도: 약 `60.842도`
- 어깨에서 손까지의 체인 신장 비율: 약 `0.989`

즉 오른팔은 어깨에서 손까지 거의 완전히 펴진 채 옆·앞 방향으로 뻗어 있다. 원본처럼
몸통 옆으로 자연스럽게 내려온 팔이 아니다. 사용자 화면에서 팔이 실제 어깨가 아닌 낮은
부위에 붙은 것처럼 보이는 이유도 본 이름 하나가 아니라, 상완 외형과 어깨 장갑 사이의
접속 위치·방향·실루엣이 함께 맞지 않기 때문이다.

오른팔 수정 기준은 `RightShoulder` 또는 `RightArm` 이름의 Transform 위치가 아니다.
실제 메시에서 흉곽과 삼각근 장갑이 만나는 어깨 소켓 중심을 먼저 찾고, 상완 메시의 접속
단면 중심과 축을 그곳에 맞춰야 한다. 그다음 팔꿈치와 손목에 원본과 같은 작은 굴곡을
부여한다.

### 4.2 방패 팔

현재 승인 자세는 왼팔에만 rest pose 변경이 남아 있다.

- 변경된 rest bone: `LeftArm`, `LeftForeArm`, `LeftHand`
- 상완의 아래쪽 기준 각도: 약 `70.031도`
- 전완의 아래쪽 기준 각도: 약 `89.974도`
- 어깨에서 손까지의 체인 신장 비율: 약 `0.444`

방패 방향과 위치를 맞추기 위해 왼팔 체인이 크게 접힌 상태다. 방패 면은 거의 정면·수직에
가깝지만, 팔과 몸통 정면을 다시 맞출 때 현재 왼손 목표점만 고정하면 어깨 접속부나 팔꿈치가
비정상적으로 꺾일 수 있다. 실제 왼쪽 어깨 소켓에서 손잡이까지 상완·전완 길이를 보존하는
2본 해법으로 다시 풀어야 한다.

### 4.3 애니메이션 영향

현재 Move 소스에서 확인된 회전 변화 범위는 다음과 같다.

- 왼쪽: 어깨 약 `9.12도`, 상완 약 `31.14도`, 전완 약 `28.04도`
- 오른쪽: 어깨 약 `10.61도`, 상완 약 `28.78도`, 전완 약 `34.93도`

정적 자세만 고치고 기존 Move 곡선을 절대 회전처럼 그대로 사용하면 접속부가 다시 어긋날
수 있다. 정적 기준 자세를 먼저 확정한 뒤, 소스 애니메이션의 기준 프레임 대비 상대 변화량만
새 기준 자세 위에 합성해야 한다.

## 5. 현재 얼굴 분석

### 5.1 직접 보이는 문제

원본은 이마판·양안·코·턱이 정면 수직축에 놓인다. 사용자가 제공한 현재 Unity 화면에서는
얼굴과 후드가 정면 카메라에 대해 사선인 3/4 실루엣을 보인다. 한쪽 얼굴 측면과 후드 폭이
반대쪽보다 더 노출되므로, 눈이 화면상 좌우로 나뉘어 보이는 것만으로 정면이라 판정할 수
없다.

현재 정확한 얼굴 yaw 각도는 기존 저장 자료만으로 확정하지 않는다. 기존 수치는 아래의
잘못된 기준을 다시 측정한 값이고, 사용자 화면 원본 파일은 현재 지정 경로에서 열리지 않아
픽셀 기반 각도를 새로 산출할 수 없었다. 따라서 임의의 각도를 추측해 적용하지 않고,
실제 얼굴판 기준을 만든 뒤 그 기준으로 현행 각도를 다시 측정한다.

### 5.2 기존 얼굴 정렬 방식의 구조적 문제

`KursaForwardHeadAlignmentTool`의 현재 로직은 다음 방식이다.

1. 승인 얼굴 머티리얼의 스킨 메시를 bake한다.
2. `UV2/UV3`의 `(0.5, 0.5)`와 `UV4` 깊이에서 좌우 눈 투영 중심을 복원한다.
3. 두 눈을 잇는 선과 `head_end` 방향으로 얼굴 좌우·위쪽 축을 만든다.
4. 그 두 축의 외적으로 만든 방향을 모델 로컬 `+Z`에 맞추도록 `Head`를 회전한다.
5. Idle과 Move도 전 구간을 샘플링하면서 같은 계산으로 `Head` 회전 곡선을 다시 쓴다.

검사 보고서 자체에도 `FaceSurfaceNormalsUsed=False`,
`EyeProjectionCentersUsedForDirection=True`라고 기록되어 있다. 즉 실제 마스크 전면, 코,
턱, 후드 실루엣은 방향 판정에 포함되지 않는다.

눈은 별도 눈알 메시가 아니라 얼굴 메시 위에 그려지는 카메라 정면 원형 렌즈 패스다. 이
눈 투영 중심을 얼굴 방향의 원인으로 사용하면, 표시된 눈은 정면처럼 보여도 얼굴 금속판은
사선을 보는 순환 판정이 생길 수 있다. `head_end` 역시 위쪽 보조 기준일 뿐 얼굴 전면을
보증하지 않는다.

또한 턱 전면 정점 15개는 `Head`, `neck`, `Spine`의 혼합 가중치를 가진다. 따라서 실제
얼굴·턱·후드 전체가 단일 `Head` 회전만으로 강체처럼 함께 정렬된다고 전제할 수 없다.
부위별 스킨 영향도를 먼저 확인한 뒤 목과 머리의 회전 분담을 정해야 한다.

### 5.3 정적·Idle·Move의 분리 필요성

- 정적 슬롯 10개는 씬의 `Head` Transform 오버라이드 영향을 받는다.
- Idle은 `Kursa_02_GroundedIdle.anim`의 `Head` 회전 곡선을 가진다.
- Move는 `neck`, `Head`, `head_end`, `headfront`를 포함한 곡선을 가진다.

따라서 한 개의 현재 프레임만 돌려서는 12개 전체가 고쳐지지 않는다. 정적 기준 자세,
Idle의 상대 머리 움직임, Move의 목·머리 상대 움직임을 각각 보존하는 방식이 필요하다.

## 6. 통합 수정 계획

아래 단계는 계획이며 이번 작업에서는 실행하지 않는다. 실제 제작은 아트 샘플 승인과 별도
Unity 적용 승인을 받은 뒤 진행한다.

### 1단계: 현행 상태를 같은 카메라 조건으로 고정

- 모델 로컬 `+Z`를 바라보는 정사영 정면 카메라를 기준으로 삼는다.
- 정적 대표, Idle 중간, Move `25%/50%/75%`를 동일한 거리·높이·화각으로 비교한다.
- 정면과 좌우 사선 보기는 원근 왜곡 확인용으로만 사용하고, 정면 판정은 정면 카메라에서
  한다.
- 몸통, 양쪽 실제 어깨 소켓, 팔꿈치, 손목, 양안, 코 융기, 턱 끝을 화면에 표시한다.

### 2단계: 본이 아닌 실제 메시 기준 좌표계를 만든다

- 몸통: 흉갑과 복부 장갑의 좌우 대응점 및 수직 중심선을 사용한다.
- 어깨: 흉곽과 상완 장갑의 실제 접속 단면 중심·반경·축을 좌우 각각 구한다.
- 얼굴: 눈 셰이더 중심이 아니라 얼굴 금속 메시의 좌우 안와 테두리, 코 융기, 턱 중앙,
  좌우 외곽 대응점을 사용한다.
- 얼굴 전면 방향은 선택된 전면 패치의 대칭면 또는 안정적인 평면 적합으로 구하고, 뒤쪽·
  측면·후드 정점은 계산에서 제외한다.
- 계산된 얼굴 전면이 모델 뒤쪽을 향하지 않도록 원본 정면 이미지와 모델 로컬 `+Z`로
  부호를 확정한다.

### 3단계: 정면 통합 아트 샘플을 먼저 제작한다

- 현재 복구 상태를 기준으로 하며 과거 오른팔 위치 조작이나 몸통 회전을 재사용하지 않는다.
- 한 샘플 안에서 몸통, 양쪽 어깨 소켓, 양팔, 목, 얼굴판을 함께 정렬한다.
- 수정 순서는 `몸통 → 실제 어깨 소켓 → 상완 → 전완 → 손 → 목 → Head/얼굴판 → 눈
  투영`으로 고정한다.
- 오른팔은 실제 오른쪽 어깨에서 시작해 몸통 옆으로 내려오게 하고, 겨드랑이 부착처럼
  보이지 않는지 정면 실루엣으로 확인한다.
- 왼팔은 실제 왼쪽 어깨 연결을 유지하면서 손이 방패 손잡이에 닿도록 다시 푼다.
- 얼굴은 얼굴판 법선과 코·턱 중심선이 모델 로컬 정면에 일치하게 한다. 눈 렌즈 위치는
  최종 얼굴 자세를 따라 다시 계산하며 얼굴 방향의 기준으로 사용하지 않는다.
- 원본 정면과 현재 상태를 나란히 둔 전신 정면, 상체 확대, 얼굴 확대를 사용자에게 제시해
  승인받는다.

### 4단계: 목과 머리의 회전 분담을 확정한다

- 얼굴판·턱·후드 정점의 `Spine`/`neck`/`Head` 가중치 비율과 실제 변형을 확인한다.
- 얼굴 외형이 `Head`에 충분히 종속되어 강체로 움직이면 `Head` 중심으로 정렬한다.
- 혼합 가중치 때문에 턱이나 후드가 비틀리면 `neck`과 `Head`에 회전을 분담한다.
- 스킨 가중치 자체의 오류가 확인될 때만 아트 샘플에서 가중치 수정안을 별도로 제시한다.
  확인 없이 본 위치나 가중치를 임의로 바꾸지 않는다.

### 5단계: 정적 12개와 애니메이션에 분리 적용한다

- 정적 슬롯은 승인된 기준 pose를 동일하게 적용한다.
- Idle과 Move는 소스 기준 프레임 대비 각 본의 상대 회전 변화량을 추출한다.
- 새 애니메이션 회전은 개념적으로
  `승인 기준 회전 × (소스 현재 회전 × 소스 기준 회전의 역회전)`으로 합성한다.
- Move의 `neck`·`Head` 움직임과 양팔 스윙은 없애지 않고, 새 기준 자세 위에 상대 변화만
  보존한다.
- `headfront`와 `head_end`는 검사용 보조 마커로만 유지하고 실제 얼굴판 방향을 대신하지
  않게 한다.

### 6단계: 직접 시각 판정

완료는 수치만으로 판정하지 않는다. 다음 항목을 실제 화면에서 모두 확인해야 한다.

- 정면에서 흉갑·복부 장갑의 중심선이 곧고 양 어깨가 자연스럽다.
- 방패 없는 오른팔이 실제 오른쪽 어깨에 연결되어 있고 겨드랑이나 몸통 옆면에서 시작해
  보이지 않는다.
- 양쪽 상완 접속부에 틈, 관통, 급격한 꺾임이 없다.
- 방패 팔의 어깨·팔꿈치·손목 연결이 자연스럽고 손이 손잡이를 유지한다.
- 얼굴판이 3/4 실루엣이 아니라 정면이며, 양안·코·턱이 같은 수직 중심선에 놓인다.
- 정적 12개와 Idle 중간, Move `25%/50%/75%`에서 같은 기준을 유지한다.
- 좌우 사선 보기에서 목·턱·후드가 찌그러지거나 얼굴에서 분리되지 않는다.

수치는 접속 오차와 재현성을 확인하는 보조 자료로만 사용한다. 사용자 직접 화면 판정이
실패하면 수치가 통과해도 완료로 처리하지 않는다.

## 7. 변경 보호 범위

- 현재 승인된 텍스처·머티리얼·눈 크기·발광 형태는 정면 정렬에 꼭 필요한 투영 갱신 외에는
  변경하지 않는다.
- 방패의 승인된 외형과 세로·정면 방향을 보존한다.
- 쿠르사 외의 적대 개체와 다른 씬 루트는 건드리지 않는다.
- 과거 실패 코드를 그대로 재실행하거나 과거 오른팔·몸통 조작값을 복원하지 않는다.
- 새 백업본을 임의로 만들지 않는다.
