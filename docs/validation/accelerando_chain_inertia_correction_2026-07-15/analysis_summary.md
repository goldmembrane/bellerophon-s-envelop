# Accelerando 사슬·철퇴 관성 수정 검증 요약

## 입력 영상 분석

- 입력: `Bellerophon - CargoRunMvp - Windows, Mac, Linux - Unity 6.3 LTS (6000.3.16f1) _DX12_ 2026-07-15 09-42-43.mp4`
- 길이 `11.588초`, H.264 `1920x1000`.
- `source_overview_contact_sheet.png`와 0.1초 간격 연속 시트 3개로 더듬이와 철퇴의 상대 운동을 확인했다.
- 같은 더듬이 입력 위상에서도 철퇴 위치가 크게 달라지고, 입력이 약해진 뒤에도 큰 원운동이 누적되는 현상을 확인했다.

## 원인

- 공격 체인은 조인트 솔버가 끝난 뒤 모든 링크의 `Rigidbody.position`과 `linearVelocity`를 순차적으로 직접 투영했다. 이 후처리가 솔버의 운동량 전달을 덮어쓰고 다음 물리 스텝에 새 오차를 만들었다.
- 실제 링크 충돌 형상이 아닌 단순 구형 프록시들이 비인접 링크 및 반대편 체인과 충돌해 더듬이 입력과 무관한 임펄스를 만들 수 있었다.
- 기존 검증은 전후축 증폭을 `1.12배` 이상 강제하면서 측면 원운동, 입력 없는 에너지 증가, 3차원 반대 방향 관성을 검사하지 않았다.

## 수정된 물리 전달

- 더듬이 끝의 키네마틱 `Rigidbody.MovePosition/MoveRotation`만 체인의 입력으로 사용한다.
- 일반 운동은 12링크 `ConfigurableJoint`의 잠긴 선형 제약과 동적 Rigidbody 운동량으로 전달한다.
- 물리 스텝 뒤 위치·속도를 직접 덮어쓰는 수동 투영을 제거했다.
- 생성 구형 프록시 상호 충돌을 제외해 단순 충돌 형상에서 생기는 허위 임펄스를 차단했다.
- 공격 링크의 솔버 반복을 position `32`, velocity `16`으로 높였다.
- 내장 Joint Projection은 링크 이탈이 `0.008`을 넘는 솔버 실패에서만 복구 장치로 사용한다.
- `AttackJointProjectionDistance`는 정상 관성 운동이 아니라 위 연결 허용 오차를 기록하는 공격 전용 상수다.

## 검증 결과

- 동일 전용 검증을 두 번 연속 실행했고 수치가 동일했다.
- 링크 최대 이탈: Left `0.007996`, Right `0.007997`.
- 더듬이 반동과 철퇴의 3차원 반대 방향 표본: Left `9`, Right `11`.
- 정지 후반 평균 철퇴 속도: Left `0.715`, Right `0.721`.
- 정지 구간 기계적 에너지 변화: Left `-0.290`, Right `-5.249`.
- 최대 측면 이탈: Left `1.388`, Right `1.503`, 허용 `1.60` 이내.
- 철퇴 메시·프록시 분리 `0`, 사슬·철퇴 Transform 애니메이션 커브 `0`.
- 검증 통과 뒤 최종 캡처를 한 번 실행했다.
