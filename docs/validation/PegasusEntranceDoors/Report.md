# Pegasus 출입구 작업 결과 — 2026-09-27

## 직접 확인 결과

- `OpenForward/00..19.png`, `OpenReverseOblique/00..19.png`: 실행모드에서 기존 Player 카메라로 활성 내부 셔터 20개를 양방향 관찰. 셔터가 상단 하우징에 수납되고 통로가 열린 모습을 확인했다. 카메라 관찰은 실제 보행 통과 판정과 구분한다.
- `Control75Percent`, `Control50Percent`, `Control25Percent`: 기존 통제실 내구도 상태를 75/100, 50/100, 25/100으로 바꾼 뒤 단계별 셔터 폐쇄를 관찰했다.
- `OverclockRelease`: 기존 동력실 장치 작동 후 재개방. `DamageAfterOverclock`: 추가 손상 후 재폐쇄. `ControlDestroyed`: 내구도 0에서 개방.
- `ArmoryPurifying/04,05,06,07,16,17.png`: 무기실 정화 중 해당 연결 문 폐쇄. `ArmoryPurificationEnded/04,16.png`: 정화 타이머 종료 후 개방.
- H01 보행은 열린 문을 지나 기존 복도 바닥 아래로 추락했다. 전체 통행 검증 실패로 기록한다.
- 창고 연결부에서 자유 이동을 끈 런타임 Player 설정 복제본과 가상 키보드 W 입력으로 이동했다. 실제 경로는 InputAction → Motor → CharacterController이며, 시작 위치만 배치했다. 화면 일부는 벽/천장 위주라 충분한 전체 통행 시각 근거로 사용하지 않는다. `Walk_11_-1_0.0`은 닫힌 창고-동력실 문에 접근해 멈춘 기록이지만 모든 문의 물리 차단 통과를 의미하지 않는다.

## 반영 사항

- 활성 H01~H05, 창고 연결 복도 5개의 양 끝 셔터에 기본 열림과 기존 상태 연동을 저장했다.
- 문 본체·장갑면·경고띠만 기존 하우징 안에 수납하며, 열림에서 문 Collider를 끄고 닫힘에서 본체 Collider를 켠다.
- 문을 매 프레임 무조건 열지 않고 내구도/봉쇄/오버클럭 조건의 상태 변화에 따라 전환한다.
- 방·복도·연결부·외형 배치, 바닥 충돌체, 공유 Player 설정, 외부 배출구, 숨긴 구형 경사 복도는 수정하지 않았다.

## 보조 확인 및 남은 문제

- 기존 H01 `straight floor slab`의 BoxCollider가 비활성화되어 있었다. 바닥 수정은 수행하지 않았다. 전체 보행 합격으로 보고하지 않는다.
- 해킹, 임시 개방 장치, 복도 정화는 실제 문을 구동할 기존 실행 상태를 찾지 못했다. 신규 기능 구현 완료로 보고하지 않는다. 오버클럭 해제와 AI 경로 판단의 통합 검증도 남는다.
- 시작 백업과 저장된 씬의 YAML 변경은 문 GameObject 20개, Transform 60개, 새 MonoBehaviour 20개. 바닥 Collider 변경 없음.
- 마지막 실행모드 종료 후 별도 저장한 씬 복사본은 디스크 Pegasus와 전체 텍스트가 같다. Dirty 표시를 이유로 사용자 변경을 버리거나 강제 복원하지 않았다.
- 마지막 콘솔은 `Compiling=False`, `Entries=0`. Play Mode 종료, 임시 입력 제거 및 설정 복제본 해제. Unity 에디터는 재시작하지 않았다.
- 자동 테스트, 빌드, Git 커밋/푸시는 실행하지 않았다. 전체 완료 판정과 최종 완료 캡처는 하지 않았다.

## 실패 시도 구분

- 최초 관찰 도구의 LookAtDirect 오버로드 컴파일 오류는 수정했다.
- 초기 잘못된 관찰 구도와 내구도 375/250 입력(현재 MaxDurability=100으로 clamp됨)은 유효한 개폐 검증이 아니다. `Damage75`, `Damage75Running` 자료를 합격 근거로 쓰지 않는다. 이후 올바른 75/50/25/0 값으로 재확인했다.
- 수치와 로그는 위 직접 관찰의 보조 자료이며, 통행 실패를 뒤집지 않는다.
