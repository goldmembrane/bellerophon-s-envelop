# Accelerando 철퇴·사슬 PhysX 진자 모션 수정 검증

## 작업 목표와 입력 영상

- 대상: `Approved Accelerando Enemy Placement/Accelerando_03_Antenna_Strike`
- 입력 영상: `Bellerophon - CargoRunMvp - Windows, Mac, Linux - Unity 6.3 LTS (6000.3.16f1)_ _DX12_ 2026-07-15 10-55-16.mp4`
- 영상 사양: H.264, `1920x1000`, `218`프레임, `6.490700초`
- 목표: 철퇴 위치나 속도를 명시적으로 추종시키지 않고, 더듬이 끝의 kinematic 물리 앵커에서 전달되는 Unity PhysX 관절 장력·중력·질량·감쇠만으로 사슬과 철퇴가 움직이게 한다.

## 영상 및 원인 분석

- 영상에서는 더듬이가 전방으로 다시 움직이는 후기 구간에도 철퇴가 뒤에 남아, 사슬 장력이 다음 입력을 회수하지 못하는 것처럼 보였다.
- 공격 리그는 이미 dynamic `Rigidbody + Collider + ConfigurableJoint`를 사용하고 있었지만, 더듬이 앵커 속도가 `1.00` 아래로 `0.18초` 유지되면 철퇴 선형 감쇠가 `0.10 -> 3.40`, 각 감쇠가 `0.35 -> 2.00`으로 상승했다.
- 이 애니메이션 입력 속도 기반 감쇠 전환 때문에 느린 전방 이동도 정지로 분류돼, 철퇴가 관절 장력에 회수되기보다 뒤에서 강하게 제동되는 상태가 생길 수 있었다.
- 원본 영상의 전체·구간 프레임은 이 폴더의 `source_*.png`에 저장했다.

## 최종 물리 구성

- 공격 중과 회복 중에 같은 Unity PhysX 감쇠를 사용한다.
  - 링크 선형/각 감쇠 `0.55 / 1.00`
  - 철퇴 선형/각 감쇠 `0.10 / 0.35`
- 애니메이션 속도에 따른 감쇠 변경 코드를 제거했다.
- 정지는 `Rigidbody.sleepThreshold = 0.015`와 일정 감쇠, 관절 충격량, 중력에 맡겼다.
- 링크 질량 `0.05`, 철퇴 질량 `0.45`, 철퇴 관절 massScale `1.00`을 사용한다.
- 더듬이는 kinematic 앵커의 위치만 `MovePosition`으로 제공하고, 12링크 사슬과 철퇴는 dynamic Rigidbody 및 잠긴 선형/자유 각도 `ConfigurableJoint`가 구동한다.
- 공격 중 모든 follower에 적용하는 spring, damper, inertia force는 `0`이며 철퇴·사슬 Transform, 위치, 회전, `linearVelocity`를 직접 지정하지 않는다.
- Unity Joint Projection은 정상 운동 생성이 아니라 솔버 실패 시 비상 연속성 복구용 `0.008`을 유지했다. 부동소수점 경계 오검출 방지를 위해 검증 허용치만 `0.0081`로 기록했다.
- 공격 AnimationClip, Animator, 더듬이 키프레임과 씬 직렬화 값은 수정하지 않았다.

## 물리 검증 보강

- 마지막 링크 방향으로 계산한 비중력 철퇴 가속도를 측정해 실제 관절 장력이 철퇴를 구동하는지 검사한다.
- 더듬이가 전진하면서 철퇴가 기준 위치보다 뒤에 있을 때, 철퇴가 전방으로 가속되는 장력 회수 표본 비율을 검사한다.
- 더듬이가 전진하는데 철퇴 속도가 뒤쪽인 상태의 최대 연속시간을 `0.18초` 이하로 제한한다.
- 기존 3차원 가속 후행, 전방 범위, 횡이탈, 에너지 비증가, 사슬 연속성, 시각 메시-프록시 일치 검증을 함께 유지한다.
- 진자는 위치에너지가 운동에너지로 바뀌며 후기 순간 속도가 초기보다 높아질 수 있으므로 후기/초기 속도비는 `3.00`으로 보정했다. 대신 후기 절대 속도 상한은 `10.00 -> 6.00`으로 강화하고 총 기계적 에너지 감소를 필수로 유지했다.
