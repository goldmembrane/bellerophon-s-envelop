## 원인 결론

가장 직접적인 원인은 공격 슬롯 전용 보정 메시가 양쪽 더듬이 후보를 수집하면서도 실제 보정을 리그 기준 `Right` 쪽에만 적용한다는 점이다.

- 공격 클립이 직접 움직이는 체인:
  - 리그 `Right`: `Bone_008 → Bone_007 → Bone_006`
  - 리그 `Left`: `Bone_011 → Bone_010 → Bone_009`
- 각 체인 옆에 나란히 있으나 공격 클립이 움직이지 않는 평행 체인:
  - 리그 `Right`: `Bone_014 → Bone_013 → Bone_012`
  - 리그 `Left`: `Bone_017 → Bone_016 → Bone_015`
- 현재 보정 함수는 `leftCandidates`와 `rightCandidates`를 모두 찾지만 `foreach (rightVertexIndex in rightCandidates)`만 수행한다.
- 현재 처리된 쪽은 왼쪽 기준 웨이트를 복사하면서 `011/010/009/017/016/015 → 008/007/006/008/007/006`으로 합쳐, 고정 평행 체인의 영향을 제거한다.
- 반대쪽 원본 웨이트에는 `Bone_017/016/015` 영향이 남는다. 공격 클립은 `Bone_011/010/009`만 크게 회전시키므로, 같은 더듬이 표면의 일부는 이동 체인을 따라가고 일부는 평행 고정 체인에 남는다.
- 현재 `40/28/14`도의 과감한 공격 자세에서 두 체인 사이 거리가 커질 때, 그 사이 삼각형이 영상처럼 길고 얇게 잡아당겨진다.

영상의 화면 왼쪽/오른쪽과 본 이름의 `Left`/`Right`는 모델 회전과 카메라 방향 때문에 혼동될 수 있다. 이 문서에서는 영상 위치는 `화면 왼쪽`, 코드·본은 `리그 Left/Right`로 구분한다. 영상에서 늘어나는 쪽은 현재 보정되지 않은 리그 `Left` 체인 쪽과 일치한다.

## 기존 검증이 놓친 이유

- `ValidateForwardStrikeAntennaDeformation`은 `Bone_008/007/006` 영향 정점만 `rightVertices`로 모은다.
- 고정 체인 영향, 릴리스 이동량, 삼각형 붕괴·과신장 검사도 모두 이 `rightVertices`에만 적용된다.
- `Bone_011/010/009` 쪽 정점 집합을 만드는 대칭 검사가 없다.
- 공격 단계별 근접 캡처도 `Bone_008/007/006`과 오른쪽 물리 앵커를 중심으로 잡아, 영상에서 깨진 반대쪽을 품질 판정 범위에 포함하지 않았다.

따라서 기존 `RightAntenna... PASS`는 보정된 한쪽에는 유효하지만 양쪽 더듬이 전체의 통과 결과는 아니다.

## 수정 계획

### 1. 현재 공격 모션 고정

- 사용자가 만족한 공격 클립의 길이, 키 시간, `40/28/14`도 회전, 빠른 전방 타격과 느슨한 복귀 타이밍을 변경하지 않는다.
- `AccelerandoChainPhysicsRig`, Rigidbody, ConfigurableJoint, 사슬 12링, 철퇴 물리 파라미터를 변경하지 않는다.
- 구현 전후에 공격 클립의 바인딩, 키 값, 길이를 비교해 메시 보정 작업이 모션에 영향을 주지 않았음을 확인한다.

### 2. 공격 슬롯 전용 메시를 승인 원본에서 양쪽 대칭으로 보정

- 이미 보정된 `.asset`을 다시 입력으로 사용하지 않고 승인된 원본 GLB의 스킨 웨이트에서 매번 생성한다.
- 현재 정상인 리그 `Right` 결과는 그대로 재현한다.
- 보정되지 않은 리그 `Left`에 다음 병합을 추가한다.
  - `Bone_017 → Bone_011`
  - `Bone_016 → Bone_010`
  - `Bone_015 → Bone_009`
- 대상 정점은 단순히 모델 좌우 좌표만으로 고르지 않는다. 해당 더듬이 본 영향을 가진 정점, 더듬이의 연결된 삼각형 영역, 안테나 뿌리 위치를 함께 사용해 몸체나 다른 부위를 잘못 포함하지 않게 제한한다.
- 몸체 접합부의 공통 루트 본 웨이트는 유지하고, 병합 후 웨이트를 정규화해 뿌리의 자연스러운 연결을 보존한다.
- 정점 위치, 정점 수, 삼각형, UV, bind pose, root bone, 머티리얼과 텍스처는 변경하지 않는다.

### 3. 양쪽 독립 변형 검증 추가

- 리그 `Right`와 `Left` 정점 집합을 각각 만들고 같은 기준으로 따로 검사한다.
- 각 쪽에서 대응하는 고정 평행 체인 영향 정점이 0개인지 확인한다.
- 릴리스 자세에서 강한 안테나 웨이트를 가진 정점이 거의 고정된 채 남는지 검사한다.
- 중립 대비 정점 변위, 삼각형 면적비, 붕괴 삼각형 수, 과신장 삼각형 수를 양쪽 모두 기록한다.
- 중립 자세의 원본 대비 정점 차이 0, 토폴로지·UV·머티리얼 불변을 확인한다.
- 한쪽만 통과하면 전체 실패로 처리한다.

### 4. 실제 Game View 반복 재생으로 확인

- 준비, 릴리스, 최대 전방 구동, 유지, 느슨한 복귀, 중립 복귀에서 양쪽 더듬이 근접 이미지를 각각 남긴다.
- `AnimationClip.SampleAnimation` 정지 화면만 보지 않고 Animator와 물리 사슬이 함께 실행되는 Game View에서 여러 공격 주기를 확인한다.
- 이번 영상에서 문제가 가장 잘 보이는 2.00~2.75초 상당의 자세를 포함해, 화면 왼쪽 더듬이가 띠처럼 납작해지거나 몸체 쪽에 고정된 부분을 남기지 않는지 비교한다.

### 5. 공격 성능 회귀 확인

- 현재 전용 검증 기준인 왼쪽/오른쪽 철퇴 전방 최대 이동 `1.051 / 1.609`, 더듬이 전방 타격 속도 `18.871 / 18.423`, 프록시 분리 `0`을 비교 기준으로 사용한다.
- 메시 웨이트만 바꾸므로 공격 각도와 물리 설정은 동일해야 한다. 측정치가 눈에 띄게 감소하거나 방향이 달라지면 완료로 처리하지 않고 원인을 다시 분리한다.
- Harness, EditMode, PlayMode, Build, Ensure, Smoke는 이 전용 애니메이션 검증에 포함하지 않는다.

## 완료 판정 기준

- 현재 만족된 휘두름 각도와 타격/복귀 타이밍이 그대로다.
- 양쪽 더듬이의 고정 평행 체인 잔여 영향이 대상 영역에서 0이다.
- 양쪽 모두 릴리스 시 거의 고정된 정점 0, 과신장 삼각형 0이다.
- 중립 메시 형상과 렌더링 자산은 승인 원본과 동일하다.
- 실제 Game View의 여러 공격 주기에서 화면 왼쪽 더듬이가 더 이상 길고 얇은 띠로 늘어나지 않는다.
- 사슬과 철퇴는 기존과 같이 더듬이 움직임을 물리적으로 추종하며 전방 타격 성능이 유지된다.
