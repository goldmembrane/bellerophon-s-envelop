# 파르붐 직접 물기 누락 및 2.5배 확대

## 범위와 상태

- 승인 범위: 조종실 일부 벽의 직접 물기 누락 수정, 기존 파르붐 외형·피격 범위 2.5배 확대, 실제 확대된 애니메이션에 따른 공격 접근/접촉 재설정.
- Pegasus의 기존 ParvumGameplay 컨테이너 아래 AI 개체와 게임용 프리팹만 확대했다. 컨테이너 배율은 1, 개체 배율은 2.5. 방·복도·벽·플레이어·기존 카메라·조명·원본 모델·클립은 변경하지 않았다.
- 현재 상태: 승인된 물기 누락 수정·외형/피격 확대·공격 접촉 재설정 완료. 직접 물기/화물 섭취/확대된 몸체의 방 이동 관찰 및 최종 재확인을 마쳤다. 파르붐의 모든 외부 시스템 연동 또는 게임 전체의 완료를 뜻하지 않는다.

## 직접 관찰과 원인

- `WallBiteSizeBefore`: 조종실 `rear bay wall left shoulder`의 기존 문제 위치에서 실제 실행 물기 관찰. 입이 벽에 도달하지만 직접 물기 이벤트가 없었다.
- 기존 코드가 몸체 목표 방향 대신 옆으로 벌어지는 입 끝 접촉점까지 정면 내적 0.98로 제한했다. 또한 프레임마다 가장 앞선 꼭짓점 하나를 골라 다른 입술 꼭짓점으로 바뀌는 선분을 추적했다.
- 방향은 목표 벽을 향하는 몸체 기준으로 확인한다. 실제 입 앞부분의 표면 꼭짓점을 같은 인덱스의 이전 프레임 위치와 연결해 추적한다. 한 물기 주기에 한 번만 피해를 준다. 근접 거리 또는 누적 시간만으로 직접 피해를 주지 않는다.
- 접촉 없는 헛물기는 시설 공격 시간에 누적하지 않는다. 성공한 0.5초 물기 주기만 누적한다. 시설 피해량, 화물 피해량, 지속 피해량과 발생 기준은 유지한다.

## 크기와 공격 거리

- 기존 피격 캡슐 0.35m × 0.4m × 0.35m → 0.875m × 1m × 0.875m. 기존 개체 전체의 균일 배율을 사용한다.
- 실제 확대된 물기에서 입 앞쪽이 전방 약 1.5m까지 움직이는 것을 확인했다. 접근 정지 기준 1.25m, 보조 상한 1.55m를 설정했다. 상한 안이어도 실제 입 접촉이 없으면 피해 없음. 금속 감지 5m와 이동 속도는 유지한다.
- `WallBiteSizeAfter01`: 0.85m 접근 설정에서는 직접 피해가 있었지만 일부 벽에 과도하게 겹쳐 최종값으로 채택하지 않았다.
- `WallBiteSizeCalibrated`: 1.4m 접근 + 단일 꼭짓점 추적에서는 좁은 벽의 접촉을 놓쳐 실패했다.
- `WallBiteSizeLipPatch`: 실제 입 표면 추적과 1.25m 접근으로 동일한 조종실 벽의 물기/직접 피해를 확인했다. 이미지에서 입을 벌리고 벽을 무는 동작을 비교했다. 최종 캡처가 아닌 반복 중간 관찰이다.
- `WallBiteSizeResolved`: 접촉 비용 보완까지 포함한 최종 코드로 같은 조종실 왼쪽 벽을 다시 관찰했다. 15초 연속 접근/물기 관찰에서 입 동작과 실제 직접 피해를 재확인했다. 최종 1회 캡처 `BiteSizeFinal.png`는 검증 후 상태 기록이며, 뒤쪽 구도인 이 이미지 하나로 물기 접촉 통과를 주장하지 않는다. 직접 접촉 근거는 앞선 측면 연속 관찰이다.

## 회귀 관찰

- `WallBiteSizeRooms`는 첫 접근 설정 당시 여섯 공간실 벽 물기 관찰이다. 최종 접근 설정의 전체 재확인을 대신하지 않는다.
- `WallBiteSizeFinalRooms` 첫 재확인에서는 동력실에서 물기 누락이 발생했다. 모든 입 표면 정점에 무거운 삼각형 접촉 질의를 반복해 실행 프레임 간격이 커졌고 물기 순간을 놓쳤다. 해당 시도를 통과로 판정하지 않았다. 입 표면의 근접 중복 정점을 작은 셀로 묶고, 벽 삼각형 경계 상자를 캐시해 불필요한 접촉 질의를 제외했다. 접촉 허용 거리나 피해량을 늘려 숨기지 않았다. `WallBiteSizeFinalRooms02`에서 동력실의 같은 위치/설정으로 직접 물기 피해가 다시 확인됐다.
- `WallBiteSizeFinalRooms02`: 최종 접촉 코드로 동력실/조종실/통제실/무기실/비품실/창고에서 실제 물기 동작과 직접 피해를 재확인했다. 가림이 있던 무기실·비품실은 `WallBiteSupplyTopSizeRooms` 상부 관찰을 추가했다. 화면상 접촉 확인과 이벤트 기록을 함께 사용했고, 영상이 가려진 프레임 단독으로 통과시키지 않았다.
- `WallBiteSizeReach`: 실제 AI가 임시 생체 표적을 향해 접근/물기, 스피커 파괴, 피격 및 사망 모션을 수행했다. 생체 직접 피해 6, 스피커 파괴 피해 3. 기존 벽 너머 표적은 피해 0. 먼 표적은 초기 위치에서 피해가 없었다. 일부 초기 표적 위치는 단상/벽의 영향을 받았으며 해당 구간을 정상 접근 완료 근거로 쓰지 않는다.
- 창고 단상은 바닥과 아래가 떨어져 있다. 크기 확대 후에도 낮은 20cm 보조 단차 광선을 보존하고 실제 캡슐 크기에 따른 전방·천장 충돌 검사와 기존 최대 단차 32cm를 사용한다.
- `BiteSizeCargo`에서 실제 저장된 개체가 실제 CH-03 금속 화물로 접근해 섭취했다. 처음 화면은 구조물에 가려져 시각 통과 근거에서 제외했다. `WallBiteSupplyTopSizeCargo`로 관찰 시점을 바꿔 위에서 실제 입과 화물 표면의 접촉을 확인했다. 물기 이벤트 기록은 관찰 라벨 변경 전후 두 `_Bites.txt`에 이어진다. 120회째 직접 섭취 기준 60.0000초, 내구도 0. 같은 화물을 이동하거나 원본 메시/충돌체를 바꾸지 않았다.
- 최종 접촉 비용 개선 후 `WallBiteSupplyTopSizeCargoFinal` 재시도는 금속 조건 입력이 늦어 이미 화물에서 5m 밖으로 벗어난 상태여서 화물 접촉 근거로 제외했다. `WallBiteSupplyTopSizeCargoReady`는 동일 프리팹/저장된 시작 위치의 임시 개체가 첫 물리 틱 전에 금속 조건을 받게 시작했다. 실제 화물 위치와 다른 먹이는 그대로 두었다. 상부 화면에서 접근/물기/접촉 확인, 120회째 직접 섭취 기준 60.0000초에 내구도 0 및 Search 복귀를 최종 코드로 다시 확인했다.
- `BiteSizeRelocation`: 같은 저장된 개체가 창고 내구도 0 조건에서 경사 복도를 걸어 조종실에 들어간 뒤 실제 벽을 섭취했다. 조종실 내구도 소진 후 통제실 복도로 이동해 통제실 벽 섭취까지 이어졌다. 입구/경사 중간/조종실 도착/통제실 복도 프레임을 직접 확인했다. 단상/장식 격자와 모델 하단이 겹치는 기존 표현은 남아 있으며 이를 완전한 외형 무관통 상태라고 주장하지 않는다. 시설 형상은 보존했다.

## 반영·제한

- 열린 에디터의 `Refresh-UnityProject.ps1` 및 `Invoke-UnityEditorBridge.ps1 -Command ReviewParvumGameplay` 사용. 실제 Play의 임시 관찰 카메라 렌더를 열어 확인했으며 키보드 직접 조작을 했다고 주장하지 않는다.
- 최초 반영 도구는 컨테이너와 하위 AI를 혼동해 중단됐다. 저장 전 오류였고 컨테이너 배율을 원래 1로 복구한 뒤 하위 AI만 반영했다.
- 전용 NavMesh의 반경/높이는 확대된 프리팹 캡슐에서 읽어 갱신했다. 원본 공간 형상과 다른 개체용 설정은 변경하지 않았다.
- 종료 상태: Pegasus Play=False, Dirty=False, Compiling=False, Console_BiteSizeClosed Entries=0. 임시 개체와 재현용 방/화물 상태는 Play 종료로 제거됐으며 원래 개체의 저장 위치 (53.9395, -4.0480, 4.9777), 체력 55 유지. 확대 설정과 전용 NavMesh는 저장됐다.
- Unity 재시작, 자동 테스트/빌드, Git 커밋·푸시 미실행. 새 컴파일 오류·실행 오류 없음. 기존 에디터 코드의 obsolete/unused 컴파일 경고는 무관한 범위라 수정하지 않았다.
- `git diff --check`는 Unity 씬 직렬화의 빈 `m_Name: ` 등 기존 변경분의 후행 공백을 보고했다. 무관한 씬 전체 포맷 정리는 하지 않았다.
