# 파르붐 내구도 소진 방 이탈

## 범위

- 현재 방의 내구도가 0이면 기존 먹이 탐색과 별도의 `RelocateRoom` 상태로 다른 살아 있는 방에 이동한다.
- 기존 반격/스피커 우선순위를 보존한다. 이동 종료 후 현재 위치 기준 5m 금속 탐색으로 복귀한다. 감지 거리, 실제 물기 접촉, 피해량/섭취 속도는 바꾸지 않는다.
- 고정된 구형 지도 좌표 대신 기존 시설 벽의 방 식별자와 실제 발밑 충돌체의 공간실 루트를 사용한다. 방/복도 형상, 충돌체, NavMesh, 원본 모델/클립을 수정하지 않는다.
- 목적지는 공간실 내부 바닥의 NavMesh 후보를 1.5m 간격으로 조사해 완전한 물리 이동 경로 중 길이가 가장 짧은 후보를 선정한다. 수학적으로 연속 공간의 최단 경로를 증명한 것은 아니다.
- 목적지 소진, 통행 차단 시 재선정. 유효한 경로가 없으면 대기 후 재시도하며 벽 통과/순간이동을 허용하지 않는다.

## 직접 실행 관찰 및 중간 실패

- `RoomRelocation01`: 저장된 실제 파르붐의 자연 섭취로 창고 내구도 소진 → 조종실 이동/섭취 → 조종실 소진 → 동력실 이동/섭취. `0064`, `0076`, `0152` 화면에서 경사 복도 및 동력실 입구 진입 확인. 키보드로 직접 조작한 것이 아니라 기존 AI/Rigidbody의 실행 화면을 Camera.Render로 관찰했다.
- `RoomRelocationConditions`: 이동 중 목적지 내구도를 0으로 주입해 재선정, 현재 방 봉쇄/해제 시 닫힌 문 앞 대기 및 재개방 후 이동 확인. 런타임 조건이며 씬에 저장하지 않았다.
- 임시 스피커/공격자 표적의 첫 두 관찰은 높이와 작은 충돌 표면 때문에 접촉 확인 실패. 실패를 통과 근거로 사용하지 않았다. 실제 물리 바닥에 표적을 놓은 `RoomRelocationRecovery`에서 실제 물기 접촉(스피커/공격자) 후 방 이동 복귀 확인. 경사 위 소형 표적의 접촉 실패는 일반 전투 AI 전체 검증으로 확대하지 않는다.
- `RoomRelocationPhysical`: 물리 바닥 높이를 경로 검사에 반영한 뒤 시작 위치 → 조종실 도착/섭취, 모든 방 0에서 대기, 복구 후 섭취 재개 확인.
- 중앙 단상 주변 특정 출발 위치 `(55.402, -4.435, 8.002)`에서 이동 실패가 반복되어 별도 재현했다. `RoomRelocationBlockedRetry`는 장애물 앞 대기, `RoomRelocationDetour`는 우회 후 다른 단상 가장자리 왕복으로 실패했다. 두 기록은 최종 통과 자료가 아니다.
- 후속 조사 `RelocationGeometry.txt`에서 CH-04 단상 하부가 바닥보다 약 14cm 높은 것을 특정했다. 기존 발밑 4cm 단차 감지 광선은 그 아래로 지나가 몸통만 걸렸다. 20cm 높이 보조 광선을 추가하되 최대 단차 32cm, 천장 CapsuleCast, Rigidbody 이동은 유지했다. 바닥판을 벽으로 오판한 과도한 하부 경로 차단은 제거했다.
- 최종 경로는 실제 바닥 높이/단차와 상부 충돌 여유를 확인하고, 직접 경로뿐 아니라 지역 우회 경로도 거리 비교에 포함한다. 씬/NavMesh를 다시 만들지 않았다.
- `RoomRelocationStepProbe`: 동일 실패 시작 위치에서 단상 통과 → 경사 복도 → 약 12초 조종실 진입 → 실제 벽 섭취 확인. 이후 33.851초 방 봉쇄, 45.527초 해제, 51.459초 목적지 통제실 소진 주입. 닫힌 문 대기 후 다시 이동하고, 소진된 통제실에서 멈추지 않고 무기실로 재선정/진입했다. 화면 `0084`는 닫힌 문 대기, `0096`은 복도 이동, `0112`는 통제실 통과다.
- 같은 실행에서 스피커 접근 중 피격 → 공격자 물기(6 피해) → 스피커 물기/파괴 → 섭취 복귀 확인. 105.544초 모든 방 0 조건에서는 목적지 없이 대기했다. 임시 표적은 실제 장비 구현 완료를 의미하지 않는다.

## 상태

요청한 **내구도 0 방 이탈 로직**의 구현·직접 실행 관찰은 완료했다. 파르붐 전체 AI 완료를 뜻하지 않는다.

- 최종 거리 비교 보완 후 저장된 원래 개체/시작 위치로 `RoomRelocationFinalRun`을 관찰했다. 현재 방 내구도만 실행 중 0으로 설정했으며 실제 이동·방 진입·섭취 상태 전환은 AI가 수행했다. 화면 `0004`/`0024`의 창고·경사 이동, `0032`의 조종실 벽 접근을 직접 확인했다.
- `RoomRelocationFinal.png`는 검사 후 1회 생성했다. 도착한 조종실에서의 상태 기록이며 모든 물기 타격 성공의 근거가 아니다.
- 최종 종료 상태: Pegasus, Play=False, Dirty=False, Compiling=False, 콘솔 Entries=0. 원래 활성 파르붐과 시작 위치 `(53.9395, -4.0480, 4.9777)` 복귀 확인. 임시 개체·조건은 실행모드 종료로 제거했다. 씬 저장/원본 모델·클립·NavMesh 수정은 수행하지 않았다.

## 별도 발견 사항 — 미해결

- 최종 실행의 조종실 `rear bay wall left shoulder`에서 Consume/Attack 복귀는 확인했지만, 일부 자세에서 직접 물기 피해가 누락되고 3초당 10의 지속 피해만 적용되는 구간을 발견했다. `RoomRelocationFinalRun.txt` 및 해당 화면에 남겼다. 방 이동 로직 검증과 구분하며 정상적인 직접 섭취 완료로 주장하지 않는다.
- 이 현상은 벽 물기 접촉/접근 자세의 별도 조사 대상이다. 본 작업에서 기존 입 접촉 판정·공격 범위·공격 모션을 임의로 바꾸지 않았다.

기존 단상/바닥 격자와 모델의 시각적 겹침은 별도 문제로 남겨 둔다. Unity 재시작, 자동 테스트/빌드, Git 커밋/푸시는 수행하지 않는다.
