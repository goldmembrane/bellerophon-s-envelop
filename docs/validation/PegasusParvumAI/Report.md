## 직접 관찰 및 실패 기록

- Source_Parvum_* 화면에서 실제 원본 외형을 확인했다.
- 임시 동작 비교 인스턴스 5개를 Pegasus 실행 중 만들고 종료 시 정리했다. 최초 비교는 구조물 가림, 두 번째는 잘못된 카메라 경계 계산으로 판정 불가였으며 채택하지 않았다. 이후 구조물 없는 임시 비교 위치에서 공격의 입 벌림/물기, 이동 변형, 대기, 피격, 사망의 납작한 최종 형태를 확인했다. 비교 개체는 실제 보행 성공 근거가 아니다.
- 실제 AI 개체에서 Rigidbody 이동과 바닥 접촉을 관찰했다. 제어 자극으로 첫 공격자 A 접근/물기, 다른 공격자 B의 후속 피격에도 A 유지, 스피커 접근 도중 피격 후 B 보복, B가 추적 범위를 벗어난 후 스피커 재접근/파괴와 현재 위치 금속 섭취 복귀, 사망 정지를 관찰했다. `Scenario.txt`와 연속 관찰 화면 참조. 임시 공격자/스피커 자극은 사용자 실제 장비 조작 검증을 대체하지 않는다.
- 최초 NavMeshPath 필드 초기화 예외는 Awake 초기화로 변경했다.
- 비볼록 MeshCollider.ClosestPoint 사용 오류로 먼 표면을 잘못 선택한 실행은 실패 처리했다. 실제 삼각형 표면 최근접점 계산으로 변경했다.
- 모션 메시 교체 시 Animator.Rebind 바인딩 오류를 제거하고 게임용 통합 변형 메시로 변경했다.
- 첫 행동 시나리오는 임시 목표가 실제 바닥 아래 탐색 면에 놓여 접근하지 못했다. 목표 배치에 실제 바닥/완전 경로 확인을 추가하고 AI 경로 시작점도 NavMesh에 투영하되 Rigidbody 위치는 강제 이동시키지 않았다. 재실행에서 실제 접근했다.
- Unity LayerSettings 캐시 공유 위반 1회 원문을 관찰 과정에서 확인했다. 캐시 직접 편집/삭제와 에디터 재시작 없이 후속 실행에서 콘솔 0건을 확인했다. 근본 원인 해결로 주장하지 않는다.

- `FacilityObserve`는 실제 시설을 먹는 AI에 정지 상태 입력을 주어 중단/재개의 Idle/Attack 전환을 직접 확인했다. 저장된 방 내구도는 유지하고 실행 중에만 창고 500 조건을 사용했다. 2~5초 중단 동안 섭취 누적 유지, 누적 정확히 5.000초에서 wound=False, 5.100초에서 True. 두 번째 중단 중 누적 6.040초로 고정된 상태에서 11.035초에 내구도 400→390 지속 피해. 파괴 외형은 없으며 이 결과는 데이터/피해 처리에 한정한다.
- 다른 분류군과 목표가 겹칠 때 사용할 `NotifyObjectiveConflict` 수신부, 씨앗체 간 우발 피해 후 보복 목표를 만들지 않는 처리, 우르제레 지원 등록/해제 수신부를 추가했다. 다른 개체 AI 및 구역 발동 제공자는 이번에 새로 만들지 않았다. 플레이어 정수 체력에는 25% 강화의 소수 피해를 누적해 반올림 과대 피해를 방지한다. 시설/화물의 별도 섭취 시간 규칙은 유지한다.
- 빈손 무기 사용 시 정의 조회 예외가 나지 않도록 물리 조준 연결을 보완했고, 막대 투척의 기존 최대 사거리 5m를 참조했다. 금속 계약 재질 조회는 계약/운송 회차별로 캐시하고 새 운송 시 화물 섭취 장부를 초기화한다.
- 수평/경사 복도 본체의 실제 물리 이동 관찰을 진행 중이다. 임시 동일 프리팹의 초기 위치만 배치하고 이동하는 스피커 입력을 추종시킨다. 본체 도착 허용은 물기 사거리 1.05m이며 입구 연결부 전체 통과와 구분한다. 첫 관찰의 일부 카메라가 벽에 가려져 채택하지 않고 카메라 장애물 회피 후 다시 관찰 중이다.

### 이전 단계 기록 및 미완료 범위

- 금속 화물 피해 기준은 최종 지시로 확정: 처음 섭취할 때 남은 내구도 / 120씩 0.5초마다 직접 섭취, 누적 60초에 0. 시설과 같은 속도라는 중간 지시는 폐기. 전용 장부는 중단 중 감소하지 않고 재접근해도 초기화하지 않는다. 실제 CH-03 본체에 화물 대상/CurrentCargoState를 연결했다. 계약 재질을 기존 공통 판별 로직으로 확인하며 재질 미정은 임의로 금속으로 판정하지 않는다. 화물에는 시설 파괴 부위/DOT를 적용하지 않는다.
