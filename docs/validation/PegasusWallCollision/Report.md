# Pegasus 벽 통과 수정 — 2026-09-27

## 직접 확인

- 수정 전 조종실 rear stem left wall을 향해 보행하자 벽을 지나 바닥 밖으로 추락했다. `wallProbe_0_1_0.0_BeforeCockpit/000.png`, `001.png`에서 벽 앞/외부로 떨어진 화면을 확인했다.
- 수정 후 동일 위치·입력으로 벽 앞에 멈추며, 비스듬히 밀어도 벽을 통과하지 않았다. 조종실·동력실·통제실·무기실·비품실·창고의 벽과 활성 복도 10곳 측벽에서도 실제 카메라 화면과 이동 기록을 확인했다. 벽 가까이 접근한 화면은 단색에 가깝기 때문에 접촉 전후 위치·충돌 대상 기록을 보조 근거로 함께 사용했다.
- 기존 Player 입력 시스템에 가상 키보드 W를 공급하고 기존 Motor/CharacterController로 이동했다. 각 확인 시작점만 배치하고 이동 중 강제 위치 이동, 자유 비행, 숙이기, 점프는 사용하지 않았다. 물리 키보드를 손으로 조작한 검증은 아니다.
- 중앙·좌우 0.8m 경로를 양방향으로 확인했다. 60개 직선 경로 중 59개 도착. 창고→동력실 +0.8m 경로의 마지막 목표점은 곡면 벽 모서리에 너무 가까워 막혔다. 해당 실패 기록을 보존하고, 같은 가장자리로 접근한 뒤 입구 안쪽으로 방향을 틀어 진입하는 `wallTransit_5_1_0.0_CornerTurn` 전체 보행을 추가해 정상 통행을 확인했다. 벽 충돌을 끄거나 실제 구조를 옮겨 통과시키지 않았다. 모든 가장자리 직선 경로가 통과했다고 주장하지 않는다.
- 내구도 25 상태의 H01 닫힌 셔터는 실제 전진을 차단했다(`Closed25`). 새 실행 세션에서 재개방 상태를 확인한 뒤 H01을 통과했다(`ReopenedFresh`). 내구도 125를 넣은 최초 `Closed` 시도는 최대 100으로 제한되어 차단 근거에서 제외했다. 이미 사용한 장치 재작동을 시도한 `Reopened25` 실패 역시 재개방 근거에서 제외했다.

## 수정

- 공간실 구조 벽, 출입구 측벽, 통제실 내부 칸막이, H01~H05 측벽에 실제 기존 메시를 사용하는 비볼록 MeshCollider 93개를 추가했다. 동력실 곡면 벽과 출입구 개구부를 경계 상자로 막지 않았다.
- 기존에 유효한 충돌체가 있는 창고·경사 복도·연결부는 그대로 유지했다. 장식/표지/스크린에 일괄 충돌을 추가하지 않았다.
- 씬 전후 차이는 GameObject 컴포넌트 참조 93개와 MeshCollider 93개 추가뿐이다. Transform, 렌더러, 메시, 머티리얼, 플레이어 크기·속도·시작 위치, 공용 프리팹과 물리 충돌 행렬은 변경하지 않았다.
- 복구 기준 `Before.unity`, 저장 후 `After.unity`. After와 디스크 Pegasus 전체 텍스트 일치. 이 폴더는 검증 자료이며 게임 씬으로 임포트하지 않는다.

## 최종 상태

- 실행모드 종료, 임시 입력 장치와 임시 입력 설정 정리. Pegasus 기본 문 열림과 화물칸 Player 시작 상태 보존.
- 마지막 전환 중 UnityEditor.Tools.OnEnable의 Library/StateCache/LayerSettings 공유 위반 오류 4건 발생. 원문은 `TransientConsole.txt`에 보존했다. Library 직접 편집·삭제 없이 Refresh 및 Play 진입/보행/종료를 다시 수행했으며 최종 Compiling=False, Entries=0, Dirty=False. 근본 원인이 해결됐다고 단정하지 않으며 해당 재확인에서는 재발하지 않았다.
- 확인용 최종 이미지 `Final.png`는 1회 생성. 이후 캐시 오류 재확인 보행은 `FinalRecheck`에 별도 중간 기록으로 보존했다.
- 자동 테스트·빌드, Unity 재시작, Git 커밋·푸시는 실행하지 않았다.
