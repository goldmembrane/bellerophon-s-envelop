# Pegasus 서 있는 수송자 통과 확인

## 직접 확인 결과

- 기존 수송자를 실행모드에서 보행시켜 동력실→조종실(H01), 동력실→통제실(H05) 입구에서 전진이 멈추는 현상을 재현했다. 플레이어 시점에서 낮은 천장을 확인했고, 이어서 충돌 기록으로 해당 Entrance_Slab_01/02를 특정했다.
- 수정 후 같은 입구를 서서 지나 방 안까지 도착하는 화면을 확인했다. 중앙·좌우 0.8m 경로에서 양방향 이동했으며, 실제 입력 시스템과 기존 Motor/CharacterController를 사용했다. 시작 위치 배치와 방향 조향 외에 Transform 위치를 밀어 통과시키지 않았다. 숙이기·점프 입력 없음.
- 활성 복도 10개 / 양 끝 입구 20곳을 조사했다. H01~H05와 창고–동력실·조종실·통제실·무기실·비품실 경로가 대상이다. 방 입구를 포함한 중앙/좌우 왕복 60조건에서 도착했다.
- H02 통제실 쪽처럼 꺾이는 입구는 직선 연장 경로를 폐기하고 실제 입구 방향으로 경로를 보정한 뒤 재확인했다.
- 수정한 두 입구에서 실제 플레이어 카메라를 마우스 입력으로 위쪽을 바라보며 회전시켜 천장·측벽 이음새를 확인했다. 확인한 화면에서 외부가 드러나는 틈 없음. `SeamSweep_0/`, `SeamSweep_1/`에 연속 관찰 화면을 보존했다.
- H01의 닫힌 문은 보행을 차단했고, 기존 오버클럭에 따른 재개방 후 통과했다. 문 기능 코드는 이번 작업에서 변경하지 않았다.

## 수정

- 동력실의 H01/H05 입구 천장을 약 0.4m 높이고, 맞닿는 측벽 상단·문 위 벽 부분·연결부 천장과 실링 메시를 같은 수직 변형으로 맞췄다. 바닥, 공간실·복도 배치 및 길이 불변.
- 기존 공유 메시 대신 `Assets/_Project/Art/PegasusStandingClearance/`의 전용 메시 18개를 해당 Pegasus 인스턴스에 연결했다. 원본 아트 샘플 및 공유 메시를 덮어쓰지 않았다.
- 씬 변경 컴포넌트: MeshFilter 18개, MeshCollider 10개, BoxCollider 6개. 원래 씬 내부에 직렬화되어 있던 헤더 메시 2개는 전용 에셋 참조로 전환되어 씬 내 데이터가 제거됐다. 모든 Transform과 Player 설정은 변경 없음.
- 플레이어 서 있는 높이 1.8m, 반지름 0.35m, 보행 속도·중력·입력 로직 유지. 자유 비행 사용 안 함.

## 실패와 재확인

- 초기 조사 일부와 마지막 비품실 측면, 최초 문 재개방 보행에서 포커스 변화와 입력 중단이 발생했다. 이를 구조 결함이나 통과로 단정하지 않고 기록을 보존했다.
- 검증용 입력 중에만 Input System의 BackgroundBehavior를 임시 조정하고 종료 시 복원했다. 재시도에서 통과한 결과만 채택했다. 게임의 영구 입력 설정은 변경하지 않았다.
- 최종 채택 기록: 중앙은 H01/H02/H05의 `After`, 나머지는 `InputCheck`; 측면은 `Side`, 단 비품실 3조건은 `SideRetry`. 합계 60조건. `Before`, 최초 실패한 `Side` 두 건, `Reopened`는 완료 근거가 아니다. 재개방 완료 근거는 `ReopenedRetry`이다.
- 닫힌 문 확인 `Closed`의 timeout은 의도한 이동 차단 결과이며 열린 경로 실패와 구분한다.
