# 검증 및 완료 규칙

## Harness/EditMode/PlayMode/Windows Build 검증 금지 규칙 - 절대 규칙 (2026-07-15)

- 이 섹션은 `AGENTS.md`의 기존 또는 후속 검증 사다리, 완료 기준, 승인 규칙보다 우선하는 절대 규칙이다.
- 사용자가 자신의 요청에서 먼저 명령명과 대상 범위를 직접 지정하지 않은 경우, 에이전트는 다음 작업을 수행하지 않는다.
  - `Run-HarnessValidation.ps1` 및 Harness 검증 관련 작업
  - `Run-EditModeTests.ps1` 및 EditMode 테스트 관련 작업
  - `Run-PlayModeTests.ps1` 및 PlayMode 테스트 관련 작업
  - `Build-WindowsDev.ps1` 및 Windows Build 관련 작업
- 위 금지는 명령 실행뿐 아니라 에이전트가 해당 작업을 승인 요청 목록, 작업 계획, 권장 검증, 후속 단계 또는 완료 조건에 선제적으로 포함하는 행위에도 적용한다.
- 위 금지는 해당 명령의 재실행, 실패 조사, 결과 파일·로그 확인, 결과 문서화, 관련 생성물 작성처럼 해당 검증을 전제로 한 모든 관련 작업에도 적용한다.
- 에이전트가 먼저 작성한 승인 요청이나 작업 목록에 위 항목을 포함하고 사용자가 `진행해`, `승인`, `좋아`, `계속 진행`이라고 답한 것은 위 검증 작업에 대한 사용자 직접 요청 또는 예외 승인으로 간주하지 않는다.
- 예외는 사용자가 에이전트의 승인 요청보다 먼저 자신의 메시지에서 위 명령명과 대상 범위를 명시하여 실행을 직접 요구한 경우뿐이다. 에이전트는 검증 사다리, 완료 기준, 일반적인 품질 확인 필요성을 근거로 예외를 추론하지 않는다.
- 아래 `검증 사다리` 섹션은 사용자가 위 예외 조건에 맞게 직접 요구한 경우에만 순서 참고용으로 사용하며, 기본 실행·제안·승인 요청 대상이 아니다.

## 검증 사다리

변경 범위에 따라 아래 명령을 낮은 단계부터 실행한다.

1. `.\scripts\Run-HarnessValidation.ps1`
2. `.\scripts\Run-EditModeTests.ps1`
3. `.\scripts\Run-PlayModeTests.ps1`
4. `.\scripts\Build-WindowsDev.ps1`

빌드, 씬 구성, 패키지, 프로젝트 설정을 바꿨다면 `Build-WindowsDev.ps1`까지 확인한다.

## 완료 기준

- 컴파일 에러가 없어야 한다.
- 관련 테스트가 통과해야 한다.
- Unity 콘솔 에러를 새로 만들지 않아야 한다.
- 하네스 규칙을 바꿨다면 `docs/HARNESS.md`와 관련 스크립트를 같이 갱신한다.
