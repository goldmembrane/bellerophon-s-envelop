# 진행 기록 2026-06-16

## 오늘 작업 범위

- 화물선 전체 모델링 기준 작업을 중단하고, 조종실을 작은 단위로 나누어 샘플 승인 후 Unity에 조립하는 방식으로 전환했다.
- 기존 화물선 전체 비주얼 모델링은 모델링 확인 작업에서 보이지 않도록 비활성화하는 흐름을 유지했다.
- 튜토리얼 흐름은 모델 확인을 방해하지 않도록 꺼두고, 플레이 중 자유 시점으로 확인할 수 있는 모델링 검사 카메라를 추가했다.
- 조종실 구조, 전면 파노라마 화면, 조종대, 경고등, 방향 라벨을 `artSample/` 승인 흐름에 맞춰 제작한 뒤 승인된 항목만 Unity에 반영했다.

## 적용된 조종실 항목

- CK-01 전면 유리창 / 전방 파노라마 화면: 5분할 창문을 제거하고 큰 전면 화면으로 Unity에 배치했다.
- CK-02 / CK-03 메인 조종대와 조작부: 낮은 조종대 본체, 타륜형 핸들, 오른쪽 전진 레버 형태로 제작해 Unity에 적용했다.
- CK-04 경고등: 좌우 보조 경고등은 제외하고, 스크린 위 경고등 바와 조종실 천장 중앙 비상 경고등 본체만 적용했다.
- CK-11 방향 표시 / 방 라벨: 왼쪽 동력실, 오른쪽 통제실, 뒤쪽 운송창고 방향을 표시하는 라벨을 Unity에 적용했다.
- `docs/COCKPIT_OBJECTS.md`에 조종실 오브젝트 목록과 제외/이관 항목을 따로 저장했다.

## 제외 및 이관 결정

- CK-05 화물선 전개도 / 내구도 표시 패널은 수동 조종 모드에서만 보이는 UI/HUD로 처리하기로 하고 조종실 모델링 오브젝트에서 제외했다.
- CK-06 자동 조종 상태 / 복구 패널, CK-07 긴급 수리 장치, CK-08 일반 수리 장치는 장치 쪽 작업으로 이관했다.
- CK-10 침입 감지 경고는 시각 경고 없이 사운드 경고로만 처리하기로 하고 모델링 오브젝트에서 제외했다.

## 중요 이슈

- CK-11 방향 라벨 위치를 사용자가 Unity 에디터에서 직접 편집한 뒤 스크립트에 반영하는 과정에서, 현재값 캡처 후 `Run-ApprovedCockpitDirection.ps1`를 실행해 라벨 루트가 재생성되었다.
- 그 결과 사용자가 직접 맞춘 라벨 위치가 덮어써졌고, 이 문제는 복구 완료로 기록하지 않는다.
- 이후 같은 상황에서는 재생성 스크립트를 실행하기 전에 각 오브젝트의 계층 경로, `localPosition`, `localRotation`, `localScale`을 먼저 별도 파일로 저장해야 한다.
- 사용자 편집값 반영 요청이 있을 때는 `Ensure` 계열 재생성 명령을 실행하지 말고, 현재 씬 값을 읽어 스크립트 상수만 갱신하는 절차를 먼저 사용해야 한다.

## 동력실 작업 기록

- 원본 기획서 기준으로 동력실에 들어갈 오브젝트 목록 문서 `docs/ENGINE_ROOM_OBJECTS.md`를 작성했다.
- ER-01 동력실 룸 쉘은 실제 Unity 적용 전 검토용 샘플로만 진행했다. Unity 씬, 프리팹, 런타임 자산에는 반영하지 않았다.
- 샘플 위치는 `artSample/engine_room_shell/`이며, 기존 샘플 구조에 맞춰 `blender/`, `exports/`, `renders/`, `unity_applied_comparison/`, `APPROVAL_STATUS.json`, `ASSET_MANIFEST.json`, `index.html`, `README.md` 구성을 사용했다.
- Blender 생성 스크립트 `scripts/GenerateEngineRoomShellSample.py`와 실행 스크립트 `scripts/Run-EngineRoomShellSample.ps1`를 추가했다.
- 현재 샘플 산출물은 `blender/engine_room_shell.blend`, `exports/engine_room_shell.fbx`, `exports/engine_room_shell.glb`, `renders/01_top.png`부터 `renders/06_sealed_wall.png`까지 생성되어 있다.
- 사용자 피드백에 따라 동력실 외벽은 세로 판이나 커튼식 구조가 아니라 원통형으로 둘러싸는 구조로 수정했다.
- 바닥은 비어 있는 부분이 없는 연속 원형 바닥으로 구성했다.
- 중앙 원통은 외부와 단절된 밀폐 원통이지만 투명 재질로 내부 코어와 플라즈마가 보이도록 구성했다.
- 복도 입구는 조종실, 통제실, 화물창 경사 복도 방향만 통행 가능하게 뚫었다.
- 입구 외의 동력실 외벽은 외부와 단절되어야 하므로, 입구 위쪽은 헤더 벽으로 막고 입구 양옆에는 `sealed side return wall`을 추가해 옆 공간이 새지 않도록 수정했다.
- 마지막 확인 대상은 `artSample/engine_room_shell/renders/05_inner_ring.png`, `02_cockpit_entry.png`, `03_control_entry.png`, `04_cargo_ramp.png`, `06_sealed_wall.png`이다.
- 마지막 실행에서 `Run-EngineRoomShellSample.ps1`은 셸 제한 시간으로 종료됐지만 Blender 프로세스는 이후 정상 종료했고 렌더, blend, fbx, glb 산출물은 생성된 것을 확인했다. 최종 스크립트 통과 상태로 보려면 다음 작업 시작 시 한 번 더 실행해 확인해야 한다.
- 현재 ER-01 샘플은 아직 사용자 최종 승인을 받지 않았다. 내일 이어서 할 때는 먼저 `artSample/engine_room_shell/index.html`과 렌더 이미지를 사용자가 다시 확인해야 한다.

## 동력실 다음 작업 시 주의

- ER-01은 승인 전 샘플 단계이므로 Unity에 적용하지 않는다.
- 사용자가 승인하기 전에는 동력실 룸 쉘, 중앙 원통, 복도 입구, 라벨, 머티리얼을 실제 게임 씬이나 프리팹에 붙이지 않는다.
- Unity에 적용하게 되면 하나로 합친 메시로 만들지 말고, 바닥, 외벽 섹션, 입구 헤더, 입구 양옆 리턴 벽, 중앙 투명 원통, 코어, 라벨, 경사로를 개별 오브젝트로 분리해 Inspector에서 위치와 크기를 수정할 수 있게 해야 한다.
- 사용자가 Unity에서 직접 크기나 위치를 편집한 뒤 스크립트 반영을 요청하면, 해당 편집값만 반영하고 추가 모델링, 검증, 스모크 실행 같은 다른 작업을 멋대로 하지 않는다.
