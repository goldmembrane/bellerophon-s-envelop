# MVP Implementation Order

이 문서는 Bellerophon의 첫 플레이 가능한 MVP를 어떤 순서로 구현할지 정리한 단계별 실행 계획서다. `docs/GAME_DESIGN_SOURCE.txt`에 저장한 원본 기획서와 `docs/GAME_DESIGN.md`의 확정된 방향을 기준으로 하며, 기획서에 없거나 애매한 기능은 구현 단계에 넣지 않는다.

`docs/IMPLEMENTATION_PLAN.md`는 상세 초안이다. 이 문서는 실제 구현 순서와 완료 기준을 추적하는 우선 계획서다.

## 기본 원칙

- 하네스 구조를 먼저 유지한다. 기능을 추가할 때 `Assets/_Project/Runtime`, `Assets/_Project/Editor`, `Assets/_Project/Tests`의 경계를 지킨다.
- 순수 게임 규칙은 가능한 한 `MonoBehaviour` 밖에 두고 EditMode 테스트로 검증한다.
- 씬, 입력, 카메라, 물리, UI처럼 Unity 런타임 의존성이 큰 기능은 PlayMode 테스트나 빠른 PlayMode smoke를 둔다.
- 계획을 세운 뒤 `docs/GAME_DESIGN_SOURCE.txt`와 비교해 원본 기획서에 없는 기능이 섞이지 않았는지 확인한다.
- 기획서에 없거나 애매한 기능 요구는 임의로 보강하지 않는다. 구현 전에 사용자에게 의도를 확인하고 답변을 받은 뒤 작업한다.
- 화물은 기본적으로 의뢰, 운송 상태, 손실, 보상, 정산의 대상이다. 플레이어가 화물을 직접 집기/운반/납품하는 상호작용은 게임 컨셉에 맞지 않으므로 구현하지 않는다.
- 납품과 정산은 목적지 도착 시 세션 상태를 기준으로 자동 처리한다. 플레이어가 납품 구역에서 화물과 직접 상호작용하는 구조는 어떤 단계에서도 만들지 않는다.
- 플레이어 상호작용은 선박 구역, 콘솔, 장치, 위험 대응 UI를 중심으로 둔다.
- Lethal Company는 그래픽 질감, 조명, 분위기, 협동 긴장감의 참고로만 사용한다.
- 적대 개체 외형 또는 역할은 `docs/ENEMY_REFERENCES.md`와 사용자 확인을 거친 뒤 만든다.

## 0단계: 하네스 기준선 고정

목표: 앞으로 기능을 쌓아도 프로젝트 구조와 검증 루프가 흔들리지 않게 한다.

작업:

- `Bootstrap` 씬이 항상 첫 실행 진입점인지 확인한다.
- `Run-HarnessValidation.ps1`, EditMode, PlayMode 테스트 실행 경로를 유지한다.
- 열린 Unity 에디터가 있으면 그 에디터를 활용해 검증한다.
- 신규 런타임 코드는 `Bellerophon.Runtime` 어셈블리 안에 둔다.
- 신규 에디터 도구는 `Bellerophon.Editor` 어셈블리 안에 둔다.

완료 기준:

- `scripts/Run-HarnessValidation.ps1`이 통과한다.
- Bootstrap 씬이 빌드 설정의 첫 씬이다.
- 열린 에디터 검증 경로가 동작한다.

## 1단계: 게임 세션과 상태 모델

목표: Unity 씬 없이도 테스트 가능한 운송 세션의 상태 구조를 만든다.

작업:

- 게임 세션 상태를 정의한다.
- 운송 실행 상태를 정의한다.
- 화물 운송 결과, 실패 조건, 정산 입력값의 최소 모델을 만든다.
- 시간 진행이나 틱 처리에 필요한 순수 로직을 기존 하네스 패턴에 맞춘다.

완료 기준:

- 세션 시작, 운송 시작, 운송 완료, 실패 상태 전환이 EditMode 테스트로 검증된다.
- Unity 오브젝트 없이 핵심 상태 전환을 테스트할 수 있다.

## 2단계: 1인칭 플레이어 MVP

목표: 플레이어가 1인칭 시점으로 움직이고 대상을 바라볼 수 있게 한다.

작업:

- 1인칭 카메라 회전과 기본 이동을 구현한다.
- 입력은 Unity Input System을 사용하되, 게임 규칙과 직접 결합하지 않는다.
- 이동 속도, 시야 민감도, 상호작용 거리 같은 값은 설정 데이터로 분리한다.
- 플레이 중 커서 잠금, 앉기 전환, HUD 기본 표시를 확인한다.

완료 기준:

- 테스트 씬에서 1인칭 이동과 시점 회전이 가능하다.
- 이동/시점 입력이 다른 시스템과 강하게 결합되지 않는다.
- 빠른 PlayMode smoke가 플레이어 스폰, 카메라 렌더, 커서 잠금을 검증한다.

## 3단계: 상호작용 시스템

목표: 플레이어가 같은 입력 규칙으로 선박 장치, 콘솔, 구역 상태 표시 같은 대상을 다룰 수 있게 한다.

작업:

- 상호작용 가능 대상의 공통 계약을 만든다.
- 플레이어 시야 기반 감지와 상호작용 실행 흐름을 구현한다.
- 상호작용 대상 표시명, 프롬프트, 실패 이유를 표현할 수 있게 한다.
- UI는 최소 프롬프트만 둔다.
- 화물 자체 조작이 아니라 화물 상태 확인 같은 선박 기능 상호작용만 허용한다.

완료 기준:

- 플레이어가 앞의 테스트 오브젝트를 감지하고 상호작용할 수 있다.
- 프롬프트가 대상 표시명과 동작을 보여준다.
- 상호작용 대상 추가 시 플레이어 코드를 수정하지 않아도 된다.

## 4단계: 화물선 6구역 Graybox

목표: 원본 기획서의 화물선 구조를 MVP 씬에서 걸어 다닐 수 있는 공간으로 만든다.

작업:

- 조종실, 운송창고, 무기실, 비품실, 동력실, 통제실 6구역을 만든다.
- 모든 구역이 운송창고와 연결되는 구조를 만든다.
- 비품실-무기실, 조종실-동력실, 조종실-통제실, 동력실-통제실, 통제실-무기실 복도를 만든다.
- 조종실은 전면 유리, 조종대, 동력실/통제실/운송창고 연결 방향을 알아볼 수 있게 만든다.
- 운송창고는 중앙 화물과 가장자리 이동 영역, 5개 복도 연결 지점을 만든다.
- 동력실은 중앙 원통형 동력기계와 복도 방향 표시를 둔다.
- 통제실은 대형 스크린, 가로형 스크린, 세로형 스크린 자리와 스크린 방 구조를 둔다.
- 무기실은 중앙 기둥, 포탑 핸들, 전면 스크린 자리와 비품실/통제실/운송창고 연결 방향을 둔다.
- 비품실은 비품창고 벽, 사출대 자리, 무기실/운송창고 연결 방향을 둔다.
- 방 크기, 복도 폭, 경사 길이는 임시 스케일로 진행하고 추후 실제 길이를 확정한다.

완료 기준:

- 플레이어가 6구역과 지정된 복도를 이동할 수 있다.
- 각 구역명과 복도 연결 방향을 플레이 중 확인할 수 있다.
- 각 구역의 핵심 상호작용 지점이 씬에 존재한다.
- 빠른 PlayMode smoke가 씬 로드, 플레이어 이동 가능, 주요 구역 존재를 검증한다.

## 5단계: 화물선/화물 상태 모델

목표: 화물선 구역 내구도와 화물 내구도가 운송 결과에 영향을 주는 기반을 만든다.

작업:

- 6구역 내구도 상태와 평균 내구도 계산을 만든다.
- 구역별 수리비 계산 입력을 만든다.
- 운송창고 내 화물 상태와 화물 손실률을 만든다.
- 운송창고 내구도에 따른 화물 손실률, 출발 제한, 창고 점수 계산의 최소 규칙을 만든다.
- 조종실, 동력실, 통제실, 무기실, 비품실 내구도 단계별 상태 경고를 표현한다.
- 동력실 0% 견인, 전체 파손 비용, 돈 부족 게임오버에 필요한 상태값을 준비한다.

완료 기준:

- 구역 내구도와 화물 내구도 변화가 순수 로직 테스트로 검증된다.
- 정산과 위험 이벤트가 같은 `ShipState`/`CargoState`를 참조할 수 있다.
- 기획서의 6구역 손상 기준을 코드 상수 또는 데이터 정의로 추적할 수 있다.

## 6단계: 방별 상호작용 1차

목표: 각 방의 핵심 장치를 같은 상호작용 시스템으로 조작할 수 있게 한다.

작업:

- 조종실 조종대: F 상호작용으로 수동 운행 모드 UI에 진입하는 틀을 만든다.
- 동력실 스크린: 동력기계 내구도 색상 표시와 운행당 1회 오버클럭을 만든다.
- 통제실 스크린: 구역 전개도, 구역명, 내구도 색상 표시를 만든다.
- 통제실 CCTV: 조종실, 운송창고, 동력실, 무기실 순서 전환의 1차 틀을 만든다.
- 무기실 포탑 핸들: F 상호작용으로 포탑 수동 모드 UI에 진입하는 틀을 만든다.
- 비품실 비품창고: 기본 3칸 보관 상태를 표시한다.
- 운송창고 화물: 화물 내구도와 손실률을 표시한다.

완료 기준:

- 6구역 장치가 모두 상호작용 프롬프트를 제공한다.
- 장치 상호작용 결과가 `ShipState`, `CargoState`, 또는 전용 UI 상태로 남는다.
- 아직 구현하지 않은 세부 기능은 원본의 어느 항목으로 이어지는지 문서에 남는다.

## 7단계: 기본 시작 세팅과 튜토리얼 의뢰

목표: 새 게임 시작 후 첫 운송을 시작할 수 있는 최소 흐름을 만든다.

작업:

- 협회 가입 계약서 화면의 최소 UI 흐름을 만든다.
- 계약서 이후 첫 배경을 협회 로고가 있는 행성 시작 상태로 둔다.
- 기본 화물선, 기본 방호복, 막대기 1개, 돈 0 상태를 세션에 반영한다.
- 첫 의뢰는 운행 시간 1분짜리 튜토리얼 의뢰만 노출한다.
- 튜토리얼 의뢰 수락 시 운송창고 중앙 화물을 세션 운송 대상으로 등록한다.

완료 기준:

- 새 게임에서 튜토리얼 의뢰 수락까지 진행할 수 있다.
- 첫 의뢰가 1분 운행 시간과 기본 화물 상태를 가진다.
- 시작 상태와 의뢰 수락 흐름이 EditMode 테스트 또는 UI smoke로 검증된다.

## 8단계: 자동/수동 운행 루프

목표: 화물선 운행 진행도, 자동 조종, 수동 운행 모드 전환을 연결한다.

작업:

- 기본 운행 상태를 자동 조종 모드로 둔다.
- 운행 진행도와 남은 운행 시간을 만든다.
- 조종실 내구도 50% 이하에서는 자동 조종을 사용할 수 없게 한다.
- 수동 운행 모드에서는 소행성들이 사방에 펼쳐진 1945식 화면 전환을 만든다.
- WASD 방향 입력으로 소행성을 피할 수 있게 한다.
- 수동 운행 모드에서 Esc를 누르면 자동 조종 모드로 돌아간다.
- 조종실 내구도 0%일 때 출발 불가와 운행 시간 증가 규칙을 반영한다.

완료 기준:

- 튜토리얼 의뢰의 1분 운행이 진행도 UI로 표시된다.
- 자동 조종 가능/불가 상태가 조종실 내구도에 따라 달라진다.
- 수동 운행 모드 진입/종료가 PlayMode smoke로 검증된다.

## 9단계: 도착 정산과 게임오버

목표: 목적지 도착 후 정산 항목을 최소 단위로 계산하고, 마이너스 잔액 유예와 최종 게임오버 판정을 만든다.

작업:

- 의뢰비, 화물선 손실률 보험비, 화물 손실률 패널티를 정산 금액으로 계산한다.
- 화물선 수리비와 총파손 비용은 정산에서 차감하지 않고 정비 단계 청구 예정 금액으로 산출·표시한다.
- 생존자 0명 청소 비용, 사망자 생명 보험 비용, 협회 알선비/유지비는 상태값을 만든 뒤 적용한다.
- 협회 의뢰 보수의 기본급, 거리 산정 비용, 수리비 지원금, 근속 보너스 입력을 만든다.
- 화물선 파손에 따른 정비 예정 비용, 견인 비용, 부활 비용을 정산 입력으로 만든다.
- 정산 후 돈이 부족하면 즉시 게임오버가 아니라 현재 돈을 마이너스 처리하고 다음 운행까지 진행 가능하게 한다.
- 다음 운행 정산 후에도 돈이 마이너스이면 플레이어 조작을 막고, 화물선이 보이는 전체 컷씬에서 포드가 버려지는 장면을 보여준 뒤 게임오버 화면으로 전환한다.
- 정산 UI는 결과 금액과 항목별 계산 근거를 보여준다.

완료 기준:

- 운행 완료 시 정산 UI가 자동으로 열린다.
- 같은 의뢰라도 화물 손상, 구역 손상, 사망자 수, 협회 상태에 따라 결과가 달라진다.
- 첫 마이너스 정산은 다음 운행을 허용하고, 두 번째 정산 후에도 마이너스일 때만 게임오버 판정이 순수 로직 테스트로 검증된다.
- 마이너스 확정 게임오버 시 플레이어 조작 불가 상태와 전체 컷씬/게임오버 화면 전환이 PlayMode smoke로 검증된다.

## 10단계: 행성 정비와 다음 운송 준비

목표: 운송 후 행성에서 화물선을 수리하고 다음 의뢰를 받을 준비를 한다.

작업:

- 6구역 손상도를 보여주는 수리 화면을 만든다.
- 수리 버튼으로 정산에서 산출된 수리비를 청구한 뒤 구역 내구도를 100%로 회복한다.
- 구역별 손상도에 따른 위험 요소 안내를 표시한다.
- 협회 의뢰와 개인 의뢰 목록의 기본 구조를 만든다.
- 의뢰 목록에는 보상, 운행 시간, 필요 창고 점수, 난이도를 표시한다.
- 상점, 개인 화물 수집, 업그레이드는 목록 진입점만 만들고 세부 구현은 이후 단계로 둔다.

완료 기준:

- 정산 후 수리 화면으로 이동할 수 있다.
- 손상된 화물선을 수리하면 다음 운송 조건이 갱신된다.
- 첫 운송 이후 다음 의뢰를 선택할 수 있는 상태가 된다.

## 11단계: 소행성 지대 위험 1차

목표: 첫 외부 위험인 소행성 지대를 실제 비용과 손상으로 연결한다.

작업:

- 외부 위험 이벤트 공통 데이터와 런타임 상태를 만든다.
- 위험 이벤트 발생 확률, 지속 시간, 결과 적용 규칙을 seed 기반으로 만든다.
- 소행성 지대의 흩어진 소행성 시야를 만든다.
- 자동 조종/자동 포탑 상태에서 소행성 지대를 방치했을 때의 랜덤 구역 내구도 손상 규칙을 구현한다.
- 수동 조종 모드에서는 WASD 조작으로 소행성을 회피할 수 있게 한다.
- 수동 포탑으로 소행성을 파괴하는 기능은 12단계와 연결한다.

완료 기준:

- 운송 중 소행성 지대가 발생하고 구역 내구도 또는 화물 상태를 변화시킨다.
- 소행성 지대 결과가 정산 비용으로 이어진다.
- 위험 발생과 손상 적용이 EditMode 테스트와 빠른 PlayMode smoke로 검증된다.

## 12단계: 수동 포탑과 외부 목표

목표: 무기실 포탑 수동 모드를 외부 위험 대응 수단으로 만든다.

작업:

- 포탑 수동 모드 화면 전환을 만든다. 이 화면은 모달이 아니라 수동 운행 모드처럼 전체 화면으로 전환한다.
- 마우스 조준, 좌클릭 단발/누르고 있기 연속 발사, 연사 딜레이 0.25초, 탄창 50발, 재장전 2초, 발당 50 피해 규칙을 만든다.
- 외부 목표 체력과 피격 판정을 만든다.
- 포탑 모드 중 침입자 피격 가능 상태는 상태값으로만 남기고, 실제 침입자 전투와 연결은 이후 단계에서 한다.
- 플라즈마 포는 업그레이드 기능이므로 기본 포탑 이후 단계로 둔다.

완료 기준:

- 포탑으로 외부 목표를 조준하고 파괴할 수 있다.
- 포탑 대응 성공/실패가 위험 이벤트 결과에 반영된다.
- 포탑 조작은 플레이어 이동/상호작용 코드와 분리된다.

## 13단계: 침입자/적대 개체 프레임워크

목표: 외계 생명체, 화물 자유 연대, 우주 해적 같은 침입자를 공통 구조로 다룰 수 있게 한다.

작업:

- 침입 시도, 침입 성공, 구역 배치, 목표 구역 선택 상태를 만든다.
- 적대 개체의 목표 유형을 화물 공격, 구역 점유, 플레이어 공격, 화물선 파괴로 분리한다.
- 체력, 이동속도, 공격 거리, 공격 딜레이, 목표 우선순위 같은 공통 데이터를 만든다.
- 이 단계에서는 특정 적대 개체의 외형, 이동 모션, 공격 모션, 실제 전투 연결을 구현하지 않는다.
- 구체 개체 외형과 공격 모션은 원본 또는 레퍼런스 확인 후 확정한다.

완료 기준:

- 첫 적대 개체를 추가할 수 있는 데이터와 상태 구조가 있다.
- 침입자가 어떤 구역과 상태에 영향을 줄지 테스트할 수 있다.
- 구체 개체 구현 전 사용자 확인 절차가 문서화되어 있다.

## 14단계: 첫 침입자 씨앗체 구현

목표: 첫 침입자인 씨앗체를 운송 루프에 연결한다.

작업:

- 씨앗체는 튜토리얼 첫 운행에서는 발생시키지 않고 그 이후 운행부터 발생시킨다.
- 원본 기획서 기준 씨앗체 침입 판정은 운행 중 2초마다 체크하고, 각 체크마다 15% 확률을 사용한다.
- 씨앗체 침입은 외부에서 저지할 수 없고 내부에서 처리하는 구조로 만든다.
- 선택된 씨앗체 하위 개체의 목표, 이동, 공격, 손상 적용 규칙을 구현한다.
- 침입 성공 시 특정 구역에 배치하고, 플레이어 또는 화물선 상태를 압박하게 한다.
- 침입자 처치, 실패, 운송 완료 시 정산 반영 범위를 만든다.

완료 기준:

- 튜토리얼 이후 운송 중 씨앗체가 나타나 플레이어 행동을 요구한다.
- 씨앗체 결과가 화물, 구역 내구도, 사망자 수, 비용 중 하나 이상에 영향을 준다.
- 씨앗체 구현은 원본 기획서의 역할과 어긋나지 않는다.

## 15단계: 무기류와 비품실 기본 루프

목표: 비품실과 상점에서 얻는 무기류가 운송 대응 수단이 되게 한다.

작업:

- 비품창고 3칸과 장비 분류를 만든다.
- 기본 지급 막대기와 기본 방호복 상태를 만든다.
- 막대기의 좌클릭 공격과 우클릭 던지기 모드 틀을 만든다.
- 머스켓의 좌클릭 발사와 우클릭 정밀 조준 모드 틀을 만든다.
- 머스켓/샷건 계열 탄창 표시와 R 재장전 입력 틀을 만든다. 머스켓 탄창 크기와 장전 시간 수치는 아직 확정하지 않고 골격만 만든 뒤 사용자 확인 후 확정한다.
- 상점 구매 탭과 판매 탭의 최소 구조를 만든다.
- 치료, 강화, 기타 물품은 데이터 구조만 만들고 실제 기능은 무기류 이후 단계로 둔다.
- 손에 들 수 있는 아이템 기본 3칸과 B 버리기, 좌클릭 사용 입력을 연결한다.

완료 기준:

- 플레이어가 막대기와 머스켓 상태를 소지품 또는 비품실에서 확인할 수 있다.
- 무기 보유 상태가 세션 저장 대상에 포함된다.
- 무기 사용 입력이 원본 기획서의 입력 규칙과 맞게 동작한다.

## 16단계: HUD, 맵, 분위기 1차

목표: 원본 기획서의 화면 정보와 어두운 화물선 분위기를 플레이 중 확인되게 한다.

작업:

- 화면 중앙 조준선은 표시하지 않는다.
- 왼쪽 아래 체력/보호막 표시를 만든다.
- 오른쪽 아래 맵 표시를 만든다.
- 화물선 내부 맵은 현재 위치 구역을 80% 크기로 표시한다.
- 저채도 산업적 색감, 어두운 조명, 제한된 시야를 적용한다.
- 선박 내부, 외부 위험, 침입자 신호에 필요한 기본 사운드 훅을 만든다.

완료 기준:

- 플레이 중 체력, 보호막, 맵, 현재 구역 정보를 확인할 수 있다.
- 화물선 내부가 어둡고 폐쇄적인 분위기로 보인다.
- UI가 상호작용 프롬프트와 겹치지 않는다.

## 17단계: 협동 플레이 기반

목표: 로컬 핵심 루프가 안정된 뒤 멀티플레이 동기화 대상을 확정한다.

작업:

- 플레이어 위치, 시점, 상호작용 상태를 동기화 대상으로 둔다.
- 세션 운송 상태, 화물 상태, 구역 내구도, 정산 결과를 동기화 대상으로 둔다.
- 방별 장치 상태, 위험 이벤트, 침입자 상태를 동기화 범위에 넣는다.
- Steam 기능은 플랫폼 인터페이스 뒤에 둔다.

완료 기준:

- 최소 2명이 같은 운송 세션 상태를 공유할 수 있다.
- 한 플레이어의 상호작용 결과가 다른 플레이어에게 일관되게 보인다.

## 18단계: 반복 가능한 플레이테스트 루프

목표: 매 변경마다 게임이 앞으로 나아가는지 확인할 수 있는 검증 루프를 만든다.

작업:

- MVP 수동 체크리스트를 만든다.
- 시작, 협회 계약서, 튜토리얼 의뢰 수락, 운행, 위험 대응, 도착, 정산, 수리, 다음 의뢰 선택까지 확인한다.
- 자동화 가능한 순수 규칙은 EditMode 테스트로 옮긴다.
- 핵심 씬 로딩과 플레이 진입은 빠른 PlayMode smoke로 유지한다.
- `.\scripts\Run-Phase18MvpPlaytestLoopSmoke.ps1`로 전체 MVP 반복 루프를 빠르게 검증한다.
- Windows 개발 빌드를 생성한다.

완료 기준:

- 새 기능 추가 후 최소 검증 경로가 명확하다.
- `docs/MVP_PLAYTEST_CHECKLIST.md`의 수동 체크 항목과 자동 smoke 검증 범위가 서로 대응된다.
- Windows 개발 빌드가 생성된다.

## 원본 대조 결과

- `docs/GAME_DESIGN_SOURCE.txt`의 1인칭 3D, 6구역 화물선, 운송창고 중심 연결, 조종대 F 수동 운행, 동력실 오버클럭, 통제실 스크린, 무기실 포탑, 비품실 비품창고, 운송창고 중앙 화물 구조를 반영했다.
- 화물은 운송창고에 위치한 운송 대상과 내구도/손실률 대상으로 다루며, 플레이어가 화물을 직접 집기/운반/납품하는 상호작용은 컨셉상 구현하지 않는다.
- 납품은 목적지 도착 후 정산으로 자동 연결되며, 납품 구역에서 화물 직접 상호작용하는 구조는 만들지 않는다.
- 첫 외부 위험은 소행성 지대로 확정했고, 수동 운행 모드에서 소행성을 조작으로 피하는 범위를 반영했다.
- 첫 침입자는 씨앗체로 확정했고, 원본의 튜토리얼 첫 운행 제외 조건을 반영했다.
- 첫 장비 구현 범위는 무기류로 확정했고, 막대기와 머스켓을 우선 반영했다.
- 상점, 행성 특성, 업그레이드, 전체 장비 목록, 모든 적대 개체는 원본에 있으나 이후 확장 단계로 두었다.

## 사용자 확인 반영

- 4단계 화물선 Graybox는 임시 스케일로 진행하고, 실제 방 크기/복도 폭/경사 길이는 나중에 정한다.
- 8단계 수동 운행 모드는 소행성들이 사방에 펼쳐진 화면에서 조작으로 피하는 수준까지 구현한다.
- 11단계 첫 외부 위험은 소행성 지대로 한다.
- 14단계 첫 침입자는 씨앗체로 하며, MVP 첫 구현 대상은 파르붐 1종으로 확정한다.
- 14단계 파르붐 구현은 현재 화물 모델에 재질 필드가 없으므로 금속 화물 섭취를 임의 구현하지 않고, 선박 구역 내구도 피해와 정비 수리비 반영을 우선 검증한다.
- 14단계 파르붐은 MVP graybox 월드 placeholder로 먼저 보이게 하고, 최종 생물 외형과 공격 모션은 이후 전투/아트 단계에서 교체한다.
- 15단계 첫 장비 구현은 무기류부터 시작하고, 막대기와 머스켓을 우선 후보로 둔다.
- 15단계 머스켓 탄창 크기와 장전 시간은 아직 확정하지 않고, R 재장전 입력/표시 골격만 구현한 뒤 별도 확인을 받는다.
- 화물 직접 집기/운반/납품 상호작용은 확장 보류가 아니라 게임 컨셉상 구현 금지 항목이다.
- 돈 부족은 즉시 게임오버가 아니다. 정산 후 잔액이 마이너스가 되면 다음 운행까지 허용하고, 다음 운행 정산 후에도 마이너스일 때 플레이어 조작 불가 상태의 전체 컷씬에서 화물선 포드가 버려지는 게임오버 화면으로 전환한다.
- 17단계의 이번 구현 범위는 실제 네트워크 패키지, Steam 로비, 온라인 접속을 도입하지 않고 네트워크 독립 인터페이스와 로컬 2인 세션 시뮬레이션까지로 제한한다.
- 본격적인 최대 5인 멀티플레이는 이후 서버 권한 모델, 상호작용 소유권, 위험/침입자 동기화, Steam 로비/재접속 정책을 상세히 확정한 뒤 진행한다.

## 남은 확정 필요 항목

- 씨앗체 하위 개체 중 14단계 MVP 첫 구현 대상은 파르붐 1종으로 확정했다. 푸가, 롱가 아르마, 테르고, 우르제레, 소치에타스, 몬스트룸, 미메시스는 이후 구현 전에 다시 확정한다.
- 소행성 지대의 첫 구현에서 크기 小와 크기 大를 모두 넣을지, 小부터 넣고 大를 확장할지 구현 전에 확정한다.
- 무기류는 막대기와 머스켓부터 계획에 반영했지만, 이후 무기 구현 순서는 구현 전에 확정한다.

## 첫 구현 단위

0~3단계는 이미 진행된 것으로 보고 유지한다. 다음 구현 단위는 다음이다.

1. 화물선 6구역 Graybox와 복도 구조.
2. 6구역 내구도와 운송창고 화물 상태 모델.
3. 6구역 핵심 장치의 상호작용 1차.
4. 기본 시작 세팅과 튜토리얼 의뢰.
5. 자동/수동 운행, 도착 정산, 돈 부족 게임오버.
