# MVP Implementation Order

이 문서는 Bellerophon의 첫 플레이 가능한 MVP를 어떤 순서로 구현할지 정리한 단계별 실행 계획서다. `docs/GAME_DESIGN.md`의 방향을 기준으로 하며, 탐사/회수가 아니라 1인칭 우주 화물 운송 협동 생존/공포 루프를 우선한다.

`docs/IMPLEMENTATION_PLAN.md`는 로컬 상세 초안이며 Git에는 포함하지 않는다. 이 문서는 그 전체 설계를 실제 구현 순서와 완료 기준으로 압축한 추적 대상 계획서다.

## 기본 원칙

- 하네스 구조를 먼저 유지한다. 기능을 추가할 때 `Assets/_Project/Runtime`, `Assets/_Project/Editor`, `Assets/_Project/Tests`의 경계를 지킨다.
- 순수 게임 규칙은 가능한 한 `MonoBehaviour` 밖에 두고 EditMode 테스트로 검증한다.
- 씬, 입력, 카메라, 물리, UI처럼 Unity 런타임 의존성이 큰 기능은 PlayMode 테스트나 수동 Smoke 체크를 둔다.
- Lethal Company는 그래픽 질감, 조명, 분위기, 협동 긴장감의 참고로만 사용한다.
- 적대 개체 외형은 `docs/ENEMY_REFERENCES.md`와 루트 `image/` 폴더를 먼저 확인한 뒤 만든다.

## 0단계: 하네스 기준선 고정

목표: 앞으로 기능을 쌓아도 프로젝트 구조와 검증 루프가 흔들리지 않게 한다.

작업:

- `Bootstrap` 씬이 항상 첫 실행 진입점인지 확인한다.
- `Run-HarnessValidation.ps1`, EditMode, PlayMode 테스트 실행 경로를 유지한다.
- 신규 런타임 코드는 `Bellerophon.Runtime` 어셈블리 안에 둔다.
- 신규 에디터 도구는 `Bellerophon.Editor` 어셈블리 안에 둔다.

완료 기준:

- `scripts/Run-HarnessValidation.ps1`이 통과한다.
- Bootstrap 씬이 빌드 설정의 첫 씬이다.
- 새 기능을 넣기 전 기준 커밋이 깨끗하다.

## 1단계: 게임 세션과 상태 모델

목표: Unity 씬 없이도 테스트 가능한 운송 세션의 상태 구조를 만든다.

작업:

- 게임 세션 상태를 정의한다.
- 운송 실행 상태를 정의한다.
- 화물 운송 결과, 실패 조건, 정산 입력값의 최소 모델을 만든다.
- 시간 진행이나 틱 처리에 필요한 순수 로직을 `FixedStepAccumulator` 같은 기존 하네스 패턴에 맞춘다.

완료 기준:

- 세션 시작, 운송 시작, 운송 완료, 실패 상태 전환이 EditMode 테스트로 검증된다.
- Unity 오브젝트 없이 핵심 상태 전환을 테스트할 수 있다.

## 2단계: 1인칭 플레이어 MVP

목표: 플레이어가 1인칭 시점으로 움직이고 대상을 바라볼 수 있게 한다.

작업:

- 1인칭 카메라 회전과 기본 이동을 구현한다.
- 입력은 Unity Input System을 사용하되, 게임 규칙과 직접 결합하지 않는다.
- 이동 속도, 시야 민감도, 상호작용 거리 같은 값은 설정 데이터로 분리한다.
- 새 변수를 추가하기 전 기존 설정값과 중복되는지 확인하고, 새 값의 역할을 문서 또는 코드 근처에 기록한다.

완료 기준:

- Bootstrap 이후 테스트 씬에서 1인칭 이동과 시점 회전이 가능하다.
- 이동/시점 입력이 다른 시스템과 강하게 결합되지 않는다.

## 3단계: 상호작용 시스템

목표: 플레이어가 같은 입력 규칙으로 화물, 장치, 문, 콘솔을 다룰 수 있게 한다.

작업:

- 상호작용 가능 대상의 공통 계약을 만든다.
- 플레이어 시야 기반 감지와 상호작용 실행 흐름을 구현한다.
- 상호작용 실패 이유를 표현할 수 있게 한다.
- UI는 최소 프롬프트만 둔다.

완료 기준:

- 플레이어가 앞의 테스트 오브젝트를 감지하고 상호작용할 수 있다.
- 상호작용 대상 추가 시 플레이어 코드를 수정하지 않아도 된다.

## 4단계: 화물 MVP

목표: 게임의 중심 대상인 화물을 들고, 놓고, 고정할 수 있게 한다.

작업:

- 화물 정의 데이터: 이름, 가치, 무게, 내구도, 파손 민감도.
- 화물 인스턴스 상태: 현재 손상도, 운송 상태, 고정 여부.
- 들기/놓기/고정 상호작용.
- 충돌 또는 낙하에 따른 단순 손상 처리.

완료 기준:

- 플레이어가 화물 하나를 들어 이동하고 선박 내부 고정 지점에 고정할 수 있다.
- 화물 손상 계산은 EditMode 테스트로 검증된다.

## 5단계: 운송 구역과 납품 루프

목표: 출발지에서 화물을 싣고 목적지에 납품하는 첫 번째 완주 루프를 만든다.

작업:

- 출발 구역, 선박 적재 구역, 목적지 납품 구역을 만든다.
- 화물 고정 여부와 위치를 기준으로 운송 가능 상태를 판단한다.
- 납품 완료 판정과 기본 보상 계산을 구현한다.
- 화물 상태가 정산 결과에 반영되게 한다.

완료 기준:

- 플레이어가 화물 하나를 싣고 목적지 납품 구역에서 완료할 수 있다.
- 납품 결과가 세션 상태와 정산 결과로 남는다.

## 6단계: 비용, 손실, 게임오버 압박

목표: 운송을 대충 하면 손해가 나고, 누적되면 실패하는 구조를 만든다.

작업:

- 수익, 수리비, 보험비, 벌금, 부채 계산을 만든다.
- 화물 파손과 선박 손상이 비용으로 이어지게 한다.
- 정산 화면 또는 임시 디버그 UI를 만든다.
- 게임오버 조건을 정의한다.

완료 기준:

- 같은 운송 루프라도 화물 상태와 손상 정도에 따라 결과가 달라진다.
- 부채 또는 손실 조건이 누적되면 게임오버 상태로 전환된다.

## 7단계: 선박과 환경 위험

목표: 적대 개체 없이도 운송 중 대응해야 할 위험을 만든다.

작업:

- 선박 손상 상태를 만든다.
- 정전, 문 오작동, 산소/압력 이상, 충격 이벤트 중 최소 1개를 구현한다.
- 위험 이벤트가 화물, 이동, 납품에 영향을 주게 한다.
- 위험 이벤트의 발생 조건과 지속 시간을 데이터로 분리한다.

완료 기준:

- 운송 도중 환경 이벤트가 발생하고 플레이어 행동을 요구한다.
- 이벤트 결과가 손상 또는 비용으로 연결된다.

## 8단계: 적대 개체 프레임워크

목표: 개별 적을 만들기 전에 공통 AI 구조를 만든다.

작업:

- 적대 개체 정의 데이터와 런타임 상태를 만든다.
- 감지, 추적, 조사, 공격, 이탈 같은 최소 상태 머신을 만든다.
- 소리, 시야, 거리 기반 감지 입력을 분리한다.
- 프리팹은 먼저 회색 박스 형태로 만들고, 외형은 `image/` 레퍼런스 확인 후 반영한다.

완료 기준:

- 테스트 적 하나가 플레이어를 감지하고 추적 또는 방해 행동을 한다.
- 감지/상태 전환의 핵심 규칙이 테스트 가능하다.

## 9단계: 첫 적대 개체 2~3종

목표: 수량보다 운송 루프를 다르게 흔드는 역할 구분을 만든다.

우선 후보:

- 단순 추적형: 플레이어 위치 압박.
- 소리 반응형: 조심스러운 운반을 요구.
- 화물 방해형: 운송 목적 자체를 위협.

작업:

- `docs/ENEMY_REFERENCES.md`에서 대응 이미지와 역할을 먼저 확인한다.
- 각 개체의 감지 조건, 이동 속도, 공격/방해 방식, 회피 가능성을 정의한다.
- 첫 구현은 회색 박스 프리팹으로 만들고, 이후 이미지 기반 실루엣을 적용한다.

완료 기준:

- 적대 개체가 운송을 방해하지만, 핵심 루프를 불가능하게 만들지 않는다.
- 각 개체가 서로 다른 대응 방식을 요구한다.

## 10단계: 분위기와 시청각 연출

목표: Lethal Company와 유사한 그래픽 질감과 긴장감을 Bellerophon의 운송 루프에 맞게 적용한다.

작업:

- 저채도 산업적 색감, 어두운 조명, 제한된 시야를 적용한다.
- 선박 내부와 외부 공간의 소리 거리감을 만든다.
- 위험 이벤트와 적대 개체에 사운드 신호를 붙인다.
- UI는 기능 중심으로 간결하게 유지한다.

완료 기준:

- 플레이 중 공간이 어둡고 불확실하게 느껴진다.
- 분위기는 Lethal Company를 참고하되, 목표 구조는 화물 운송으로 유지된다.

## 11단계: 협동 플레이 기반

목표: 로컬 핵심 루프가 안정된 뒤 멀티플레이 동기화 대상을 확정한다.

작업:

- 플레이어 위치, 시점, 상호작용 상태를 동기화한다.
- 화물 위치, 고정 상태, 손상 상태를 동기화한다.
- 문, 콘솔, 위험 이벤트, 적대 개체 상태를 동기화 범위에 넣는다.
- Steam 기능은 플랫폼 인터페이스 뒤에 둔다.

완료 기준:

- 최소 2명이 같은 화물을 운송할 수 있다.
- 한 플레이어의 상호작용 결과가 다른 플레이어에게 일관되게 보인다.

## 12단계: 반복 가능한 플레이테스트 루프

목표: 매 변경마다 게임이 앞으로 나아가는지 확인할 수 있는 검증 루프를 만든다.

작업:

- MVP 시나리오를 하나 정한다.
- 시작, 적재, 운송, 위험 대응, 납품, 정산까지 수동 체크리스트를 만든다.
- 자동화 가능한 순수 규칙은 EditMode 테스트로 옮긴다.
- 핵심 씬 로딩과 플레이 진입은 PlayMode Smoke 테스트로 유지한다.

완료 기준:

- 새 기능 추가 후 최소 검증 경로가 명확하다.
- Windows 개발 빌드가 생성된다.

## 첫 구현 단위

가장 먼저 구현할 구체 작업 단위는 다음이다.

1. `GameSession`과 운송 상태 모델.
2. 1인칭 플레이어 이동과 카메라.
3. 상호작용 감지와 테스트 상호작용 오브젝트.
4. 화물 하나의 들기, 놓기, 고정.
5. 납품 구역과 기본 정산.

이 다섯 가지가 끝나면 Bellerophon의 핵심 루프가 처음으로 플레이 가능한 형태가 된다.
