# 진행 기록 — 2026-09-17

## 승인 요청 Stop 훅 운영 규칙 정리

- 승인 요청 누락 검사용 `Stop` 훅은 마지막 응답에 `작업 승인 요청`이 있을 때만 검사하도록 운영 범위를 명확히 했습니다.
- 일반 완료·경과 응답은 `Stop` 훅이 상태 파일 또는 규칙 매니페스트를 읽기 전에 종료하며, 모델링·애니메이션 완료 응답의 직접 확인 근거는 훅에 의존하지 않고 에이전트가 직접 자체 점검하도록 `AGENTS.md`를 정정했습니다.
- 승인 요청 전용 `Stop` 훅은 세션 매니페스트를 생성하거나 복구하지 않으며, 시작 매니페스트 복구 책임은 `UserPromptSubmit`, `PreToolUse`, `PostToolUse`에만 둡니다.
- `.codex/` 런타임 상태와 로컬 훅 캐시는 저장소 커밋 대상에서 제외했습니다.

- 청백색 아크는 `ApprovedSample_ArcFlow_A`, `ApprovedSample_ArcFlow_B` 두 이동 레이어로 구성했습니다.
- 화면에 표시되는 승인 샘플 기반 VFX는 이동 레이어 6개만 남습니다.
  - 청백색 아크 2개
  - 주황색 스파크 2개
  - 청회색 연기 2개
- 파티클 시스템과 임의 생성 파티클 자산은 사용하지 않습니다.

## 플레이어 피해 반응 Mixamo 애니메이션 연결

- 공급 FBX의 원본 바이너리와 내장 Mixamo 애니메이션을 임의 생성 없이 프로젝트로 복사하고, 플레이어 골격에 Humanoid 리타게팅한 뒤 Generic 호환 클립으로 베이크했습니다.
- 연결 대상:
  - `Hit_Reaction` ← `player model/transfer hitted.fbx`
  - `Knockdown` 전방 넘어짐 ← `player model/transfer front fall.fbx`
  - `Knockdown` 후방 넘어짐 ← `player model/transfer back fall.fbx`
  - `Knockdown_GetUp` ← `player model/transfer getting up.fbx`
  - `Death` ← `player model/transfer dying.fbx`
- 클립 구성:
  - `Hit_Reaction`: `1.2초`, 30fps, 전체 반복
  - `Knockdown`: 전방 넘어짐 `3.1초` → 후방 넘어짐 `1.566667초` → 전방 넘어짐으로 즉시 복귀해 반복
  - `Knockdown_GetUp`: `2.7초`, 30fps, 전체 반복
  - `Death`: `3.366667초`, 30fps, 전체 반복
- 원본 FBX 애니메이션 커브는 수정하지 않았고 Root Motion은 사용하지 않습니다.
- 대상 루트 Transform, 렌더러, Avatar는 변경하지 않았습니다.

## Hit_Reaction·Knockdown·Knockdown_GetUp 자세 교정

- `Hit_Reaction`은 전신 기준 자세를 `Player_Idle`에 맞추고 공급 원본의 상대 피격 반동만 유지했습니다.
  - 첫 프레임 전신 자세와 `Player_Idle` 일치 `True`
  - 원본 상대 반동 보존 `True`
  - 오른발이 뒤로 빠지는 원본 기준 자세 제거
  - 양팔은 `Player_Idle` 로컬 자세를 유지하면서 몸통 반동을 계층적으로 추종
- `Knockdown`의 후방 넘어짐 구간은 양팔을 `Player_Idle` 로컬 자세에 맞추고 몸통 움직임을 계층 추종하게 했습니다.
- `Knockdown_GetUp`은 기상 초반·중간 원본 팔 동작을 50%까지 유지합니다.
  - 50%→70% 구간에 SmoothStep 보간 적용
  - 최종 기립이 시작되는 70% 시점에는 양팔이 이미 `Player_Idle` 자세
  - 70% 이후에는 몸통을 따라 움직이며 마지막 프레임에서 뒤늦게 보정되지 않음
  - 팔 이외 커브, 손가락 커브, 클립 길이와 루프 설정 변경 `False`
- `Death`와 `Knockdown` 전방 넘어짐 원본 동작은 변경하지 않았습니다.
