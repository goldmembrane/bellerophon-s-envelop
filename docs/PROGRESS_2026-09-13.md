## MarkerSpray_Spray 대기 모션 원본 그대로 복사·실제 개체 반복 연결 — 직접 확인 통과

### 적용 내용

- `MarkerSpray_Idle`의 현재 2D Blend Tree에서 원점 `(0, 0)`에 연결된 실제 대기 클립 `MarkerSprayIdle_Idle.anim`을 소스로 확인했다.
- 소스 AnimationClip의 곡선·키프레임·이벤트·클립 설정을 `EditorUtility.CopySerialized`로 `MarkerSpraySpray_Idle.anim`에 그대로 복사했다. 소스 클립과 복사본의 전체 직렬화 서명이 일치하며 소스 파일과 소스 컨트롤러의 해시는 반영 전후 동일하다.
- `MarkerSpraySpray_Idle.controller`를 매개변수 없는 단일 레이어·단일 상태·전이 없음으로 구성하고, 복사한 대기 클립을 기본 상태로 연결해 Loop 설정 그대로 반복 재생되게 했다.
- 최초 구현은 Controller만 연결해 실행 모드에서는 재생 가능했지만, 편집 모드의 실제 대상 Animator가 초기화되지 않아 씬 화면에서는 아무 동작도 보이지 않았다. 더구나 최초 최종 캡처가 실제 대상이 아닌 검증용 복제본에 클립을 직접 샘플링해 이 결함을 가렸다.
- 실제 대상 Animator를 `Enabled=True`, `Speed=1`, `Update Mode=Normal`, `Apply Root Motion=False`, `Always Animate`로 명시하고, 편집 모드에서는 실제 대상과 연결된 Animator Controller를 PlayableGraph로 계속 평가하도록 교정했다. 별도 복제 개체나 대체 클립을 사용하지 않는다.
- 씬 변경은 `MarkerSpray_Spray` Animator의 Controller 연결과 재생 설정에만 한정했다. `MarkerSpray_Idle`의 계층과 Animator 구성은 변경하지 않았고, `MarkerSpray_Spray`의 Transform 계층·Avatar·모델·파지·추종 구성도 변경하지 않았다.

- `Lightsaber_Off_Idle`, `Lightsaber_DiagonalSlash`, `Lightsaber_Grip_OneHand`, `Lightsaber_ThrustMode_Enter`, `Lightsaber_Thrust`, `Lightsaber_ThrustMode_Exit`의 정적 씬 리그만 수정했다. 아직 존재하지 않는 AnimationClip, Animator Controller, Blend Tree는 생성하거나 변경하지 않았다.
- 여섯 개체의 오른쪽 어깨·상완·전완·손목 회전을 몸 앞의 한손 파지 자세로 분배했다. 오른팔의 위치·스케일·부모 관계는 변경하지 않았다.
- 손가락은 기존 `Vacuum_Idle` 오른손의 실제 주먹 파지 관절 회전을 그대로 복사했다. 새 손가락 자세를 추론하거나 애니메이션으로 생성하지 않았다.
- 각 `Lightsaber_Prop`의 수정 직전 전체 월드 회전을 보존한 뒤, 팔 자세 변경 후 동일 쿼터니언을 다시 적용했다. 손잡이는 오른손 직계 자식 관계를 유지하며 손바닥 중심에만 다시 맞췄다.
- 몸통·머리·왼팔·하체·루트·Animator·모델·메시·머티리얼·텍스처는 변경하지 않았다.

### 직접 확인 결과

  - 모든 패널에서 오른팔이 몸 앞에서 자연스럽게 굽혀지고 오른손 손가락이 손잡이를 감싼다.
  - 손목의 반대 꺾임, 어깨·상완·전완 메시의 늘어짐이나 비틀림, 손잡이와 손바닥의 이탈은 보이지 않는다.
  - 여섯 손잡이 모두 작업 전의 정면 30도·수송자 기준 오른쪽 25도 기울기를 유지한다.
- 최종 캡처는 구조·수치 검사를 통과한 뒤 한 번만 생성했으며, 검증 중 대상 Transform을 조작하지 않았다.

### 보조 확인 결과

- 여섯 개체의 팔꿈치 굽힘은 `87.88123~87.88125도`, 손목 편차는 `9.548699~9.548802도`, 손바닥 파지축과 손잡이축 편차는 `9.530339~9.530360도`다.
- 손잡이 중심과 손바닥 중심의 오차는 여섯 개체 모두 `0m`, `Vacuum_Idle` 손가락 회전 복사 오차는 `0도`다.
- 적용 직전 대비 손잡이 전체 월드 회전 보존 오차는 여섯 개체 모두 `0도`다.
- 보호 스냅샷으로 오른팔 허용 회전과 손잡이 로컬 위치·회전 외 Transform, Renderer·Mesh·Material 참조, Animator 설정이 바뀌지 않았음을 확인했다.
- 최종 적용·읽기 전용 검사·최종 캡처에서 새 Unity 콘솔 오류가 발생하지 않았다.

## Lightsaber 6개 개체 오른팔을 왼팔처럼 내린 정적 파지 수정 — 직접 확인 통과

- 오른쪽 어깨는 `Player_Idle`의 내려간 오른쪽 어깨 기준 회전을 사용하고, 상완·전완은 각 대상의 왼팔 방향에 맞춰 몸 옆으로 내렸다.
- 기존 오른손 손가락 로컬 회전은 변경하지 않아 이미 적용된 주먹 파지를 그대로 유지했다.
- 각 `Lightsaber_Prop`의 작업 직전 전체 월드 회전을 보존한 뒤, 내려간 오른손의 손바닥 중심에 다시 맞췄다. 손잡이의 오른손 직계 부모 관계와 스케일도 유지했다.
- AnimationClip, Animator Controller, Blend Tree를 만들거나 변경하지 않았으며 정적 씬 리그만 수정했다.

### 직접 확인 결과

  - 여섯 대상 모두 오른팔이 왼팔처럼 몸 옆으로 내려가고 양팔 실루엣과 손 높이가 대응한다.
  - 오른손 손가락은 손잡이를 감싼 상태이며 손잡이는 손바닥에서 이탈하지 않는다.
  - 손목 역꺾임, 어깨·상완·전완 메시 늘어짐, 관절 붕괴나 손잡이의 부자연스러운 관통은 보이지 않는다.
- 최종 캡처는 구조·수치 검사를 통과한 뒤 한 번만 생성했으며, 검증 중 대상 Transform을 조작하지 않았다.

## Lightsaber 6개 상태 원본 손잡이·오른손 추종 배치 — 직접 확인 통과

### 적용 내용

- 제공 원본 `item model/lightsaber.fbx`를 `Assets/_Project/Art/Items/Lightsaber/Lightsaber.fbx`로 바이트 변경 없이 반입했다. 원본과 반입본의 SHA-256은 `A1194265AF8BEBEDCE72A40A10279BD2F60372BE437F71F04AC40C2CEFBFA930`으로 같다.
- FBX에 내장된 `base_color.jpg`, `normal.jpg`, `texture_0_metallic.png`, `texture_0_roughness.png` 4개를 빠짐없이 추출했다. 원본 metallic RGB와 roughness 역값을 smoothness 알파에 넣은 결정적 URP 채널 패킹을 만들고, 내장 `Material.001`을 외부 URP Lit 머티리얼로 복제·재매핑했다. 원본 FBX와 원본 이미지 픽셀은 수정하지 않았다.
- 원본 모델은 로컬 X축 길이 `0.01m`, 정점 `3,477개`의 단일 손잡이 메시이며 별도 광선날 메시가 없다. 임의 광선날을 생성하지 않고 제공된 손잡이와 발광구만 그대로 사용했다.
- `Lightsaber_Off_Idle`, `Lightsaber_DiagonalSlash`, `Lightsaber_Grip_OneHand`, `Lightsaber_ThrustMode_Enter`, `Lightsaber_Thrust`, `Lightsaber_ThrustMode_Exit`에 각각 `Lightsaber_Prop` 하나를 추가했다.
- 각 손잡이는 해당 수송자의 `RightHand` 직계 자식으로 배치해 손의 위치·회전을 실시간 추종한다. 손잡이 중심은 손목과 검지·중지·약지·소지 근위 손가락뼈의 중앙으로 계산한 손바닥 중심에 맞췄다.
- 원본 단위가 실제 손보다 작아 임의 고정 배율 대신 각 대상의 손목–손가락 관절 거리로 계산한 손바닥 길이의 2배가 손잡이 전체 길이가 되도록 균일 확대했다. 메시 비율과 형상은 변경하지 않았다.
