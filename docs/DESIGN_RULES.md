# 디자인 규칙

이 문서는 UI, VFX, 사운드, 비애니메이션 아트 에셋과 게임 디자인 문서 작업에 적용한다. 작업 시작 전 루트 `AGENTS.md`의 공통 규칙을 먼저 따른다.

## 기획 및 진행 문서

- 계획을 세운 뒤에는 원본 기획서 `docs/GAME_DESIGN_SOURCE.txt`와 계획이 맞는지 비교한다.
- 이어서 작업을 시작하기 전 현재 날짜를 확인한다.
- 현재 날짜의 `docs/PROGRESS_YYYY-MM-DD.md`가 있으면 먼저 읽고 현재 구현 상태와 다음 단계 범위를 확인한다.
- 현재 날짜 진행 문서가 없으면 `docs/`의 최신 `PROGRESS_YYYY-MM-DD.md`를 확인하고, 새 날짜 진행 문서 생성이 필요하면 사용자에게 확인한다.
- 고정된 과거 날짜 진행 문서만 기준으로 이어서 작업하지 않는다.
- 진행 문서가 `docs/GAME_DESIGN_SOURCE.txt` 또는 `docs/MVP_IMPLEMENTATION_ORDER.md`와 충돌하면 원본 기획서와 사용자 확인 사항을 우선한다. 애매한 부분은 구현 전에 질문한다.

## 디자인 산출물 승인

- UI, VFX, 사운드, 머티리얼을 포함한 비애니메이션 아트 작업은 실제 게임 씬, 프리팹, 런타임 자산, UI 흐름에 연결하기 전에 저장소 루트 `artSample/`에 사용자가 검사할 수 있는 샘플 파일을 먼저 저장한다.
- 기존 모델의 형상 수정, 결함 복구, 불필요한 지오메트리 제거에는 `artSample/` 제작과 샘플 선승인을 요구하지 않는다. 해당 수정은 사용자가 지정한 모델·부위·변경 범위 안에서 일반 작업 승인을 받은 뒤 직접 반영할 수 있다.
- 신규 모델 제작, 기존 모델의 새로운 시각 디자인, 텍스처·머티리얼 제작에는 기존 `artSample/` 샘플 승인 절차를 그대로 적용한다.
- 샘플은 PNG/JPG/WebP, HTML 미리보기, FBX/GLB, 독립 확인 가능한 Unity 샘플 씬·프리팹과 설명 문서처럼 사용자가 검토할 수 있는 형식이어야 한다.
- 샘플을 독립적인 그림이나 장식 시안으로만 만들지 않는다. 승인 후 어느 씬, 프리팹, 런타임 루트, 상호작용 앵커, 카메라 시점, 충돌 기준에 어떻게 반영할지 먼저 정리하고, 축척, 위치, 부품 경계, 상태 전환, 표시·비표시 조건을 샘플에 드러낸다.
- `artSample/` 설명 문구는 한국어를 기본으로 쓴다. 영어는 파일명, 코드 식별자, 고유 명사, 장비명처럼 필요한 경우에만 쓴다.
- 사용자가 샘플을 검사하고 승인한 뒤에만 실제 게임에 연결한다. 승인 전에는 씬, 프리팹, 런타임 자산, UI 흐름에 붙이지 않는다. 샘플 생성을 위한 임시 파일과 미리보기 파일은 허용한다.

## 샘플 요약 HTML

- 새 `artSample/` 샘플에는 사용자가 결과를 한 페이지에서 확인할 수 있는 요약 또는 비교 HTML을 같은 샘플 폴더에 반드시 만든다.
- HTML은 가장 가까운 기존 비교 페이지 형식을 따른다. 이슈판트 관련 작업은 `artSample/enemies/ispant_armed/Ispant_Reference_Comparison.html`의 한국어 설명, 비교 이미지, 핵심 변경 사항, 승인 및 Unity 적용 상태 구성을 기준으로 한다.
- HTML에는 검토 이미지·미디어를 상대 경로로 직접 표시하고, 주요 샘플 산출물로 이동하는 상대 링크를 제공한다. 원본 또는 목표, 수행 범위, 확인 수치나 검증 결과, 추론·생성 여부, Unity 적용 여부를 명확히 적는다.

## 시각 품질 게이트

- 아트·텍스처링 작업은 검사 가능한 `artSample/`을 먼저 저장하고 명시 승인을 받은 뒤 Unity 런타임 씬, 프리팹, 에셋, UI 흐름에 구현한다.
- 기존 모델링 수정은 `artSample/` 선승인 게이트에서 제외한다. 완료 판정은 사용자 지정 목표와 실제 반영 결과의 나란한 시각 비교 또는 사용자 직접 확인을 기준으로 한다.
- 승인된 `artSample/` 산출물은 분위기 참고가 아니라 재현 대상이다. Unity 구현은 승인된 샘플을 가능한 한 정확히 재현한다.
- Unity 구현 결과는 승인된 샘플과 반복 비교하고, 시각 일치율이 수용 가능해질 때까지 반복한다.
- 렌더러 수나 오브젝트 존재 여부 같은 내부 검증은 시각 비교를 대체하지 않는다. 품질 게이트는 사용자 승인 `artSample/`과의 시각 일치다.
- 2D 레퍼런스로 만든 승인 샘플은 레퍼런스 카메라 렌더부터 맞춘다. 보이지 않는 뒷면, 내부, 정확한 치수, 기계적 디테일은 `docs/GAME_DESIGN_SOURCE.txt`에서 도출하거나 추론임을 명시한다. 보이는 디자인 변경을 사용자 확인 없이 만들지 않는다.
- 아트 완료 판정은 목표 `artSample/` 렌더·이미지와의 나란한 시각 비교로 한다. 에셋, 렌더러, 오브젝트 수, FBX 파일, 머티리얼의 존재만으로 완료 보고하지 않는다.
